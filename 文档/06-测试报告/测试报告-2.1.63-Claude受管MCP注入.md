# 2.1.63 Claude 受管 MCP 注入测试报告

日期：2026-07-22

## 1. 问题与根因

生产绑定 `4` 对应 Worker `8`（Claude）能够输出等待用户二选一的问题，但随后把 `mc_create_watch_event` 当作 Bash 命令执行，返回 `not found`。生产中心没有新值守事件或干预记录。

根因是受管 Codex 已有命令级 MCP 注入，而 Claude start/resume 只有身份环境和提示词，没有通过 Claude CLI `--mcp-config` 注册平台 MCP Server。另发现本机没有全局 MCP profile，MCP 脚本只读取 `MC_API_KEY`，不能继承 Runtime 已配置的 `API_KEY`。

## 2. 修复

- 受管 Claude start/resume 注入临时 stdio MCP 配置。
- 注入 `MC_AGENT_ID`、`MC_WORKER_SESSION_ID`、`MC_SESSION_KIND` 和权限模式。
- MCP 脚本支持从同一 Runtime 进程继承 `API_KEY`。
- 未受管 Claude 不注入，不修改用户全局 Claude 配置。

## 4. 真实本地 CLI 证据

环境没有 `~/.mission-control/profiles/default.json`。仅保留 Runtime `API_KEY`，Claude 使用临时 `--mcp-config` 调用 `mc_session_transcript`，退出码为 `0`，最终输出为：

```text
MCP_AUTH_OK
```

这证明 Claude 能发现 MCP 工具，并且 MCP 子进程可继承 Runtime 鉴权。
