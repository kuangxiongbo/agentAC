# 接口设计-人工值守-三端协同通信优化

## 1. 接口目标

为云端服务端、本地 Web/Edge 和托盘客户端提供统一可靠消息接口，支撑人工值守 assist、session continue、权限决策和客户端状态上报。

## 2. 通用约定

### 2.1 Base URL

- 云端：`https://<center-host>` 或本地部署的 `http://127.0.0.1:3000`。
- 本地 Web：`http://127.0.0.1:5101`。

### 2.2 认证

云端管理 API：

- `Authorization: Bearer <token>` 或 `x-api-key: <api-key>`。
- 角色按现有 `viewer/operator/admin`。

Edge 消息 API：

- `x-edge-enroll-token` 或 Bridge scoped token。
- token 必须绑定 `client_id`。

### 2.3 错误模型

```json
{
  "error": "message",
  "code": "EDGE_MESSAGE_NOT_FOUND",
  "retryable": false,
  "correlation_id": "corr_xxx"
}
```

### 2.4 状态枚举

```text
pending
leased
completed
failed_retryable
dead_letter
cancelled
```

## 4. 云端消息 API

### 4.1 创建消息

```http
POST /api/edge/messages
```

权限：`operator` 或内部服务。

请求：

```json
{
  "client_id": "mc-edge-a8901a06c732",
  "type": "human_watch.assist.requested",
  "direction": "cloud_to_edge",
  "correlation_id": "corr_01",
  "idempotency_key": "assist:4:d501e3e5:fingerprint",
  "agent_ref": {
    "local_agent_id": 8,
    "agent_name": "Worker"
  },
  "session_ref": {
    "session_id": "d501e3e5-07f7-44d3-8235-311a57ccf967",
    "session_kind": "codex-cli",
    "serial_key": "mc-edge-a8901a06c732:codex-cli:d501e3e5-07f7-44d3-8235-311a57ccf967"
  },
  "payload": {}
}
```

响应：

```json
{
  "message": {},
  "created": true,
  "duplicate": false
}
```

幂等规则：相同 `tenant_id + client_id + idempotency_key` 返回已有消息，`duplicate=true`。

### 4.2 客户端拉取并领取消息

```http
POST /api/edge/messages/lease
```

调用方：本地 Web/Edge。

请求：

```json
{
  "client_id": "mc-edge-a8901a06c732",
  "lease_owner": "runtime-boot-id",
  "limit": 10,
  "lease_seconds": 120,
  "capabilities": {
    "reliable_mailbox": true,
    "human_watch_assist_v2": true
  }
}
```

响应：

```json
{
  "messages": []
}
```

服务端行为：

- 只返回 `pending` 且 `next_attempt_at <= now` 的消息。
- 同一 `serial_key` 同时只 lease 一条。
- 设置 `status=leased`、`lease_owner`、`lease_expires_at`、`attempt_count += 1`。

### 4.3 Ack 完成

```http
POST /api/edge/messages/{id}/ack
```

请求：

```json
{
  "client_id": "mc-edge-a8901a06c732",
  "lease_owner": "runtime-boot-id",
  "result": {
    "delivered": true,
    "steward_reply": "建议回复内容"
  }
}
```

响应：

```json
{
  "message": {
    "id": "msg_xxx",
    "status": "completed"
  }
}
```

### 4.4 标记失败

```http
POST /api/edge/messages/{id}/fail
```

请求：

```json
{
  "client_id": "mc-edge-a8901a06c732",
  "lease_owner": "runtime-boot-id",
  "error_code": "WORKER_SESSION_NOT_FOUND",
  "error_message": "session not found",
  "retryable": false,
  "result": {}
}
```

服务端行为：

- `retryable=true` 且未超过 `max_attempts`：`failed_retryable`，设置 `next_attempt_at`。
- `retryable=false` 或超过最大次数：`dead_letter`。

### 4.5 查询消息

```http
GET /api/edge/messages?client_id=xxx&status=pending&type=human_watch.assist.requested&limit=50
GET /api/edge/messages/{id}
```

权限：`viewer`。

用途：中心 UI 和排障。

### 4.6 取消消息

```http
POST /api/edge/messages/{id}/cancel
```

权限：`operator`。

请求：

```json
{
  "reason": "operator_cancelled"
}
```

## 5. 人工值守 Assist API 调整

### 5.1 主动值守

```http
POST /api/human-watch/assist
```

新增请求字段：

```json
{
  "delivery_mode": "auto",
  "queue_if_offline": true
}
```

响应：

```json
{
  "ok": true,
  "delivery": {
    "mode": "queued",
    "message_id": "msg_xxx",
    "correlation_id": "corr_xxx",
    "queued": true,
    "delivered": false
  },
  "binding_id": 4,
  "event_id": 123
}
```

兼容：

- 旧客户端不支持 `reliable_mailbox` 时，仍可能返回 `503 Bridge client is offline`。
- 新客户端离线时返回 `200 queued=true`。


### 7.2 托盘触发本地 drain

托盘内部调用：

```http
POST http://127.0.0.1:5101/api/local/mailbox/drain
```

触发时机：

- 本地 Web 启动成功后。
- Bridge 连接成功后。
- 收到云端 wakeup 后。
- 周期性心跳，例如 30 秒。

## 8. MCP 工具行为

### 8.1 `mc_create_watch_event`

prompt-only 调用时：

1. 本地优先调用本地 Web `/api/human-watch/assist`。
2. 如果本地处于云端托管模式，可调用云端 `/api/human-watch/assist`。
3. 请求带：
   - `delivery_mode=auto`
   - `queue_if_offline=true`
   - `worker_session_id`
   - `session_kind`
4. 返回：
   - 已投递：告诉 Worker 值守已回复。
   - 已排队：告诉 Worker “已提交值守，等待客户端在线处理”。

## 9. 测试契约

单测：

- `edge-message-service.test.ts`
- `local-mailbox.test.ts`
- `human-watch-assist-queued.test.ts`
- `tray-mailbox-status.test.ts`

集成测试：

1. 客户端离线：assist 创建 queued message。
2. 客户端上线：message 被 lease、执行、ack。
3. 执行中崩溃：lease 过期后重新执行。
4. 相同 idempotency key：不会创建重复消息。
5. 单 session 并发两条 continue：按顺序处理。
