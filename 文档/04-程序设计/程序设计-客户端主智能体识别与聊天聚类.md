# 程序设计-客户端主智能体识别与聊天聚类

## 1. 设计目标

在不破坏现有客户端功能的前提下，引入主智能体自动识别、安装入口联动、顶层 Agent 同步、创建向导限制与聊天分类。

## 2. 涉及模块

### 2.1 运行时检测

文件候选：

- `mission-control-client/src/lib/agent-runtimes.ts`
- `mission-control-client/src/app/api/agent-runtimes/route.ts`

变更目标：

1. 扩展 runtime 类型集合到 `claude/codex/openclaw/cursor/opencode/hermes`。
2. 为 Cursor 与 OpenCode 增加检测函数。
3. 为主智能体安装能力提供统一元数据。

### 2.2 主智能体安装

文件：

- `mission-control-client/src/lib/agent-runtimes.ts`
- `mission-control-client/src/app/api/agent-runtimes/route.ts`
- 相关设置/引导组件

变更目标：

1. 把主智能体安装能力与主智能体元数据统一起来。
2. 安装后刷新运行时检测与主智能体同步。
3. 对暂不支持自动安装的类型，保留统一接口和明确说明。

### 2.3 主智能体同步

建议新增模块：

- `mission-control-client/src/lib/runtime-agent-sync.ts`

职责：

1. 基于运行时检测结果生成主智能体定义。
2. 将主智能体 upsert 到 agents 表。
3. 对未检测到的主智能体做离线标记。

建议字段：

1. `source = runtime`
2. `framework = <runtime id>`
3. `parent_id = null`
4. `config.runtime_managed = true`

补充约束：

1. `source=runtime` 才属于主智能体层。
2. `source=local` 的磁盘导入智能体需要与主智能体分开展示。

### 2.4 调度入口

文件候选：

- `mission-control-client/src/lib/scheduler.ts`
- `mission-control-client/src/lib/db.ts`
- `mission-control-client/src/app/api/agents/sync/route.ts`

变更目标：

1. 启动后自动同步主智能体。
2. 手动刷新 Agent 时保证主智能体也同步。

### 2.5 创建向导

文件：

- `mission-control-client/src/components/panels/agent-detail-tabs.tsx`

变更目标：

1. 第一步改为读取主智能体候选列表。
2. 只渲染已检测到的主智能体类型。
3. 若无候选，则显示空状态提示。
4. 子智能体父节点默认优先选择对应主智能体。

### 2.6 聊天会话分组

文件：

- `mission-control-client/src/components/chat/conversation-list.tsx`
- `mission-control-client/src/components/chat/session-kind-brand.tsx`
- `mission-control-client/src/components/chat/chat-workspace.tsx`

变更目标：

1. 将当前 `gateway/local` 分类改为按主智能体类型分组。
2. 保留 active/recent 状态信息，但挂到每个类型组内。
3. 将 `gateway` 标签文案在主智能体层解释为 `OpenClaw`。

### 2.7 任务管控兼容

文件候选：

- 现有任务面板与指派逻辑

变更目标：

1. 主智能体同步后自动进入可选任务目标列表。
2. 子智能体与主智能体共用同一套任务记录。

### 2.8 本地会话执行器

文件候选：

- `mission-control-client/src/lib/local-session-executor.ts`
- `mission-control-client/src/lib/task-dispatch.ts`
- `mission-control-client/src/app/api/agents/message/route.ts`
- `mission-control-client/src/app/api/sessions/continue/route.ts`
- `mission-control-client/src/app/api/chat/messages/route.ts`

变更目标：

1. 为 `claude` / `codex` 建立统一的本地 session 执行器。
2. 当 Agent 配置了本地 `session_key` 时，可直接通过该会话接任务。
3. 当给 `claude` / `codex` Agent 发消息时，不再强制依赖 OpenClaw gateway。
4. 聊天中的本地会话继续能力与任务派发能力共享同一套底层实现。

## 3. 数据结构建议

### 3.1 主智能体定义

```ts
interface RuntimeAgentDefinition {
  runtime: 'claude' | 'codex' | 'openclaw' | 'cursor' | 'opencode' | 'hermes'
  name: string
  role: string
  status: 'offline' | 'idle'
  source: 'runtime'
  framework: string
  config: {
    runtime_managed: true
    detected: boolean
    installed: boolean
    version?: string | null
  }
}
```

### 3.2 会话分组定义

```ts
type SessionGroupKey = 'claude' | 'codex' | 'openclaw' | 'cursor' | 'opencode' | 'hermes' | 'other'
```

## 4. 兼容策略

1. 不修改现有 transcript API。
2. 不修改现有 session continue API。
3. 不修改现有 chat session prefs API。
4. 主智能体同步采用 upsert，避免影响手动创建的普通 Agent。
5. 本地磁盘导入智能体继续保留，但不再混入主智能体分组。
6. `~/.agents` 这类磁盘导入智能体需要优先从 frontmatter/config 中解析具体 framework；若无法推断，必须明确标记为 `unknown`，不能继续隐式落成 `generic`。

## 5. 风险点

1. 主智能体名称必须稳定，否则父子关系和 UI 分组会波动。
2. Cursor 与 OpenCode 的本机识别需采用尽量宽松但可解释的规则。
3. `gateway` 既是会话类型又会在主智能体层代表 OpenClaw，需要 UI 文案统一。
