# 程序设计-通用智能体中枢平台

## 1. 设计目标

把当前仓库内已经存在的中心端、客户端、桥接、会话扫描、框架接入能力整理成明确的程序级设计基线，为后续新增框架与功能提供稳定变更入口。

## 2. 代码基线

### 2.1 中心端

- 目录：`mission-control`
- 关键职责：
  - 提供中心 UI 与 API
  - 启动 scheduler
  - 启动 bridge server
  - 存储中心数据库
  - 维护 adapter 注册表

### 2.2 客户端

- 目录：`mission-control-client`
- 关键职责：
  - 扫描本机 Agent
  - 检测本机运行时
  - 扫描本机会话
  - 启动 remote bridge
  - 向中心端发送状态

## 3. 关键模块设计

### 3.1 Agent 数据表

核心设计点：

1. Agent 表必须保存 `framework`、`node_id`、`parent_id`。
2. 本地发现的 Agent 使用 `source=local`。
3. 桥接同步到中心端的 Agent 使用 `source=bridge`。

### 3.2 Remote Bridge

职责：

1. 客户端建立到中心端的 WebSocket 连接。
2. 首次发送 `hello`，携带 `clientId`、能力清单和 Agent 列表。
3. 接受中心端下发的任务、命令和 ping。
4. 上报 `agent_status` 与聊天事件。

建议的稳定消息类型：

1. `hello`
2. `welcome`
3. `ping`
4. `pong`
5. `agent_status`
6. `task_dispatch`
7. `task_ack`
8. `chat_message`
9. `command`

### 3.3 Bridge Server

职责：

1. 接收客户端连接。
2. 处理 `hello`、`agent_status`、`chat_message`。
3. 将远端 Agent 持久化到中心数据库。

### 3.4 Local Agent Sync

职责：

1. 扫描 `~/.agents`
2. 扫描 `~/.codex/agents`
3. 扫描 `~/.claude/agents`
4. 扫描 `~/.hermes/skills`

输出：

1. 本地 Agent 记录
2. 内容 hash
3. 离线标记

### 3.5 Runtime Detection

当前 runtime 列表：

1. `openclaw`
2. `hermes`
3. `claude`
4. `codex`

未来建议：

1. 为 runtime detection 增加统一接口，例如 `id`、`detectInstalled`、`detectVersion`、`detectAuth`、`detectRunning`。
2. Cursor、OpenCode、Antigravity 新增时按同样接口接入。

### 3.6 Session Scanner

当前来源：

1. OpenClaw Gateway Session
2. Claude JSONL
3. Codex JSONL
4. Hermes SQLite

未来建议：

1. 为不同来源统一映射到同一 Session DTO。
2. 新增来源时只新增 parser，不改动上层展示结构。

## 4. 接口与契约

### 4.1 Agent 创建

要求：

1. 允许携带 `framework` 和 `parent_id`。
2. 仅 `framework=openclaw` 走 Provision 路径。

### 4.2 Adapter 接入

要求：

1. 所有 adapter 提供 `register`
2. 所有 adapter 提供 `heartbeat`
3. 所有 adapter 提供 `reportTask`
4. 所有 adapter 提供 `getAssignments`
5. 所有 adapter 提供 `disconnect`

### 4.3 Status 与 Sessions 聚合

要求：

1. Status 接口对外返回当前运行时与会话能力摘要。
2. Sessions 接口对外返回统一聚合后的会话视图。

## 5. 变更控制建议

后续迭代中，若涉及新框架接入，至少评估以下代码点：

1. runtime detection 模块
2. session scanner 模块
3. local agent sync 模块
4. bridge payload 模块
5. 中心端入库与展示模块
6. adapter 注册表
7. 测试覆盖

## 6. 风险与注意事项

1. 当前服务端和客户端目录存在大量平行复制代码，变更时必须注意双端同步。
2. 默认值若仍使用 `openclaw`，容易造成对新框架的误判。
3. 不同会话来源的数据格式差异较大，统一模型时必须谨慎处理时间、token 与活跃状态。
