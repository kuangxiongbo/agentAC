# 研发流程总则

## 核心目标

建立统一的文档先行研发机制，确保后续任意需求都能通过文档快速续接，不依赖单次会话记忆。

## 强制流程

1. 先理解需求，创建或更新对应 PRD。
2. 基于 PRD 创建或更新测试用例文档。
3. 基于 PRD 创建或更新架构设计文档。
4. 基于 PRD 创建或更新程序设计文档。
5. 基于设计创建或更新任务拆解文档。
6. 仅在以上文档完成后进入编码。
7. 编码完成后执行自测试，并更新测试报告。
8. 测试完成后更新任务状态与需求状态。

## 最低交付要求

每次进入编码阶段前，至少需要存在以下文档并完成本轮更新：

- `01-PRD/PRD-<主题>.md`
- `02-测试用例/测试用例-<主题>.md`
- `03-架构设计/框架设计-<主题>.md`
- `04-程序设计/程序设计-<主题>.md`
- `05-任务拆解/任务拆解-<主题>.md`
- `06-测试报告/测试报告-<主题>.md`
- `07-状态跟踪/需求状态-<主题>.md`

## 状态定义

- `未开始`：尚未启动。
- `进行中`：当前迭代正在处理。
- `已完成`：已经实现并通过本轮自测。
- `已阻塞`：存在外部依赖或关键决策未解决。
- `已取消`：确认不再继续。

## 文档维护要求

1. PRD 负责描述目标、范围、场景、验收标准。
2. 测试用例负责描述需求对应的场景、步骤、预期结果。
3. 架构设计负责描述系统边界、数据流、部署形态。
4. 程序设计负责描述模块、接口、数据结构、变更点。
5. 任务拆解负责描述执行顺序、依赖关系、责任边界。
6. 测试报告负责记录实际执行的命令、结果、问题。
7. 状态跟踪负责记录当前完成度、剩余工作、下一步。

## 本仓库执行要求

1. 文档主目录固定为仓库根目录下的 `文档`。
2. 涉及服务端与客户端同时变更时，必须在同一主题下分别写清中心端与边缘端影响。
3. 涉及新框架接入时，必须在 PRD、测试、设计、任务文档中同时更新支持策略与验收标准。
