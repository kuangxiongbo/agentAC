# 任务拆解-人工值守 V2：结构化事件与决策闭环

## 1. 执行原则

- 先文档和模型评审，再实现。
- 第一阶段优先复用 `permission_requests`，不要一次性大迁移。
- 所有恢复动作必须有审计。
- 不允许普通聊天回复改变审批状态。
- 人在 Worker 会话内回复时，必须由 Worker/本地托管端回写平台统一决策 API，平台完成状态流转和审计。
- 默认由值守 Agent 判断并提交结构化决策/指令；只有命中高危动作清单时升级到人工通知地址。
- 规则引擎默认只发现事件，不直接代发。

## 4. 最小可发布版本定义

最小可发布版本不要求新增 `watch_events` 表，但必须满足：

1. `permission_requests.context_json.watch_event` 能表达来源、类型、恢复方式。
2. UI 用“值守事件”统一展示 pending 请求。
3. Worker MCP 主动创建和等待决策路径可用。
4. 值守 Agent MCP 决策路径可用。
5. 规则模式下不直接代发，先创建事件。
6. 决策和恢复有审计。
7. 命中高危动作清单时触发人工通知地址；通知缺失时阻断恢复并进入平台待审批。
8. 人在 Worker 会话回复后，平台能收到同步并关闭审批；未同步时不得误判完成。
9. 并发审批、通知失败、过期回复都有明确错误、审计和不恢复保障。
