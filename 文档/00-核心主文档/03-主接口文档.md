# Agent 指挥仓主接口文档

## 1. 文档控制

| 项 | 内容 |
|----|------|
| 文档状态 | 生产灰度版 |
| 接口版本 | V1.0 |

本文档是 Agent 指挥仓的唯一主接口文档，覆盖 HTTP API、Bridge、本地接口、MCP 工具、配置和发布产物接口。

## 2. 接口总览

接口类型：

- HTTP API：Next.js route handlers。
- SSE/事件：`eventBus` 和 `/api/events`。
- Bridge RPC：中心与边缘同步、读 transcript、continue、exec approval、值守记忆检索。
- 可靠 Edge 消息：云端 Relay 与本地 Mailbox 接口，覆盖人工值守 assist、session continue、权限决策补偿。
- Bridge `agent_status` 事件必须包含 `id/name/role/status`，并应包含 `framework/parent_id/session_key`。中心端必须兼容旧客户端缺失可选字段的状态包，不得把已有 `framework/session_key` 覆盖为空。
- MCP 工具：托管 Codex 调用 Mission Control 的工具出口。
- 本地 CLI/配置：Codex 启动参数、MCP 环境变量。
- 发布接口：Docker 镜像标签、托盘更新清单、客户端下载元数据。
- 发布校验接口/脚本：`pnpm run verify:release-surfaces` 在发布前校验所有版本表面和下载资产。

## 3. 认证与授权

通用约定：

- `viewer` 可读取资源。
- `operator` 可创建、变更、审批。
- 变更类接口必须经过 mutation rate limit。
- 企业高级能力还需要授权平台 entitlement 控制。
- 授权业务 `appId` 固定为 `mission-control`，必须与用户中心 SKU 的 `schema_app_id` 和 Zitadel 应用实例的 `business_app_id` 完全一致；`agentCenter` 仅作为应用/实例展示名。
- 服务端在线校验用户中心 `/api/internal/verify-access`，请求包含 `app_id/client_id`、`subject`、OIDC 实例上下文和运行阶段。
- 在线校验明确返回 `unsubscribed`、`expired`、`app_instance_mismatch`、`user_not_found`、`no_tenant` 时，接口不得用本地离线授权覆盖。
- 只有在线校验错误 `error` 或用户中心不可达时，才允许使用本地离线授权作为降级缓存。

权限请求相关：

- `GET /api/permission-requests` 需要 `viewer`。
- `POST /api/permission-requests` 需要 `operator`。
- `GET /api/permission-requests/{id}` 需要 `viewer`。
- `POST /api/permission-requests/{id}/decision` 需要 `operator`。
- `POST /api/permission-requests/{id}/worker-human-reply` 用于 Worker 原会话收到人工回复后回填平台审批结果，必须记录审计并关闭等待状态。
- MCP 工具 `mc_create_watch_event` 在未传 `options` 时用于托管 Worker 主动请求值守回复；在传 `options` 时兼容创建结构化权限请求；`mc_record_worker_human_reply` 用于记录 Worker 原会话人工回复。
- Codex 进程级 MCP 注入参数 `mcp_servers.mission_control.env` 必须是 TOML map，例如 `{ MC_URL = "...", MC_MANAGED_SESSION = "1" }`；返回 JSON 字符串属于无效配置。
- `/api/sessions/continue` 返回 `accepted/remote/reply` 后，前端必须立即展示提交或送达反馈；真实 assistant 内容仍以 transcript 刷新结果为准。
- 可靠 Edge 消息 API 必须使用统一 `message_id/correlation_id/idempotency_key/lease/ack/fail` 模型；Bridge 离线不等同业务失败，支持 mailbox 的客户端应返回 `queued=true` 并在上线后补偿执行。

授权状态相关：

- `GET /api/auth/me`：返回当前用户和有效授权；每次调用强制刷新在线授权。
- `GET /api/license/status?refresh=1`：授权设置页强制刷新授权缓存并返回当前有效授权。
- `GET /api/license/schema-template`：导出当前产品授权模板，包含 `appId=mission-control`、`enableHumanWatch`、`enableLocalCliElevation`。
- `GET /api/local-cli/elevation-entitled`：本地 Web 调用中心校验本地 CLI 提权订阅。Edge 客户端应优先发送 `x-edge-enroll-token`，中心从 scoped token 解析用户/租户后在线校验 `enableLocalCliElevation`；普通 Web/API 访问仍走 `viewer` 鉴权。

发布与下载相关：

- `GET /api/edge/download-info`：返回托盘客户端下载信息，版本以 `public/edge-tray/manifest.json` 为准。
- `GET /api/edge/download-info` 除统一 `tray_version` 外，还必须返回 `tray_downloads[]`，每项包含 `platform`、`arch_label`、`download_url`、`available`，供下载页区分 Apple Silicon 与 Intel 包。
- 当托盘本地启动失败且 `5101` 被占用时，错误信息必须区分“E-Agent Edge 自身旧 runtime 占用”与“其他软件占用”。若是其他软件，占用诊断需返回 PID、进程名和工作目录，避免误导用户执行无效重试。
- 托盘停止或重启本机 Web 客户端时，内部实现必须以进程组为单位终止当前托管进程树，然后再执行端口占用诊断和 owned 进程回收。仅终止单个 child 句柄不视为完成停止。
- `GET /api/releases/edge-runtime-manifest`：返回 Edge runtime 更新清单，版本以 `public/edge-runtime/manifest.json` 为准。
- `/edge/download` 页面必须展示 manifest 中的客户端版本，不能使用手写旧版本号。
- `pnpm run verify:release-surfaces` 必须在 Docker 构建前通过；该脚本校验服务端、本地 Web、托盘、Tauri、manifest、release docs、主文档、下载包 SHA-256 和 runtime zip 静态资源。
- 已安装托盘客户端只会在 manifest `client_version` 高于本地 runtime 版本时替换 runtime；同版本重新打包不会触发已安装用户升级。
- `GET /api/status?action=health` 的 `version` 字段是托盘判断 5101 是否为当前 runtime 的依据；托盘不得仅凭 HTTP 200 沿用旧健康进程。
- 托盘 `setup-status` 事件和 `get_setup_status` 命令返回的状态可包含 `progress`、`detail`、`downloaded_bytes`、`total_bytes`，用于展示 runtime 下载和安装阶段。`progress` 为 0-100；未知总大小时前端应显示不确定进度动画和已下载大小。
- 版本不匹配错误必须使用普通字符串展示当前运行版本和目标版本，不得向 UI 暴露 Rust `Option` 调试格式。

本地会话接口性能约束：

- `GET /api/sessions` 不得因单个 Codex JSONL 大文件整文件读取而阻塞 5101 服务；大文件只能窗口读取。
- `GET /api/sessions/transcript?kind=codex-cli` 必须支持大 JSONL 分页读取并返回 `hasMoreOlder`、`nextOlderCursor`、`sourceSize`。
- `POST /api/sessions/continue` 和提权发送不能被会话列表扫描长时间阻塞；发布验证需覆盖普通发送和 `local_cli_elevated=true` 发送。
- `POST /api/sessions/continue` 返回 `{ ok: true, accepted: true }` 表示请求已入队，不代表 assistant 回复已经完成；前端必须释放发送按钮，并通过强制 transcript 刷新追踪后续回复。
- `GET /api/sessions/transcript` 返回的 assistant 可见文本是结束等待态的依据；如果当前发送基线之后已有 assistant 文本且无未完成工具调用，UI 必须停止计时并允许继续发送。
- 本地 CLI 提权 UI 通过会话级本地偏好保存选中状态；请求接口仍以每次发送体中的 `local_cli_elevated=true` 为准，避免 UI 状态和执行权限隐式耦合。

## 4. 通用约定

请求格式：

- JSON 请求体使用 `Content-Type: application/json`。
- 时间字段优先使用 Unix 秒。
- 错误响应格式：`{ "error": "message" }`。

状态：

- 权限请求状态：`pending`、`approved`、`denied`、`expired`、`cancelled`。
- 风险级别：`low`、`medium`、`high`、`critical`。
- 决策者类型：`human_user`、`steward_agent`、`system`。

## 5. 权限请求 API

### 5.1 创建权限请求

```http
POST /api/permission-requests
```

用途：Worker、MCP 或平台创建一个需要审批的权限请求。

权限：`operator`。

请求体：

```json
{
  "id": "optional-request-id",
  "client_id": "edge-client-id",
  "worker_local_agent_id": 123,
  "worker_name": "worker",
  "worker_session_id": "session-key",
  "steward_local_agent_id": 456,
  "steward_name": "watcher",
  "request_type": "local_cli_elevation",
  "title": "需要执行高风险命令",
  "prompt": "Worker 请求执行命令，请审批。",
  "risk": "medium",
  "options": [
    { "id": "approve_once", "label": "批准一次", "action": "approve" },
    { "id": "deny", "label": "拒绝", "action": "deny" }
  ],
  "context": {
    "command": "example",
    "gateway_exec_approval_id": "optional"
  },
  "expires_at": 1780000000
}
```

响应：

```json
{
  "request": {
    "id": "request-id",
    "status": "pending",
    "risk": "medium",
    "options": []
  }
}
```

错误：

- `400`：请求体无效、缺少 title/prompt/options。
- `401/403`：鉴权或角色不足。
- `429`：变更频率限制。

### 5.2 查询权限请求列表

```http
GET /api/permission-requests?status=pending&client_id=xxx&worker_local_agent_id=1&limit=50
```

用途：平台 UI 查询待审批或历史请求。

权限：`viewer`。

查询参数：

- `status`
- `client_id`
- `worker_local_agent_id`
- `steward_local_agent_id`
- `limit`

响应：

```json
{
  "requests": [],
  "count": 0
}
```

### 5.3 查询或等待单个权限请求

```http
GET /api/permission-requests/{id}
GET /api/permission-requests/{id}?wait=1&timeout_ms=30000
```

用途：MCP/Worker 查询或等待审批结果。

权限：`viewer`。

规则：

- `wait=1` 时等待请求从 `pending` 变为终态。
- `timeout_ms` 最小 1000。
- 超时返回 `504`。

### 5.4 提交审批决定

```http
POST /api/permission-requests/{id}/decision
```

用途：人类操作者、值守 Agent 或系统提交审批决定。

权限：`operator`。

请求体：

```json
{
  "optionId": "approve_once",
  "reason": "已确认命令风险可接受",
  "deciderType": "human_user",
  "deciderAgentId": "optional-agent-id"
}
```

规则：

- 请求必须处于 `pending`。
- `optionId` 必须存在于请求 options。
- `deciderType` 必须是 `human_user`、`steward_agent` 或 `system`。
- `steward_agent` 不能批准 `high` 或 `critical` 风险。
- 如果 context 包含 `gateway_exec_approval_id`，系统会尝试转发到 Gateway exec approval。

响应：

```json
{
  "request": {
    "id": "request-id",
    "status": "approved",
    "selected_option_id": "approve_once",
    "decider_type": "human_user"
  },
  "gatewayForward": {
    "status": "applied",
    "execApprovalId": "gateway-id"
  }
}
```

转发失败响应会带 `warning`，同时请求上下文写入 `gateway_exec_forward.status=failed`。

## 6. MCP 工具接口

MCP Server：`mc-mcp-server.cjs`。

传输：stdio。

自动注入范围：

- 平台、本地 Web、托盘客户端启动的托管 Codex。
- 不包括用户自己终端直接运行的 Codex。

核心工具：

### 6.1 `mc_create_permission_request`

用途：创建权限请求。

输入：与 `POST /api/permission-requests` 对齐。

输出：创建后的 request。

### 6.2 `mc_wait_permission_request`

用途：等待指定请求的审批结果。

输入：

```json
{
  "id": "request-id",
  "timeout_ms": 30000
}
```

输出：终态 request 或超时错误。

### 6.3 `mc_decide_permission_request`

用途：提交审批决定。主要给平台内值守 Agent 或系统工具使用。

输入：

```json
{
  "id": "request-id",
  "optionId": "deny",
  "reason": "风险过高",
  "deciderType": "steward_agent"
}
```

安全边界：

- 工具本身不绕过服务端 API 权限。
- 高/关键风险批准由 API 拦截。

## 8. Bridge 与本地接口

Bridge 负责中心和边缘之间的同步与远程执行。当前发布涉及：

- WebSocket 连接必须通过 `Authorization: Bearer <token>` 或 `x-api-key` 提供 Bridge token。
- 中心 Bridge token 解析顺序为显式 Bridge token、Edge Bridge token、服务端 API key、旧 `gateway.token` 兼容值。
- 未配置 token 时默认拒绝连接；只有显式 `MC_BRIDGE_ALLOW_ANONYMOUS=1` 才允许匿名桥接。
- Agent/session 同步。
- transcript 读取。
- `sessions/continue` 写入 user 消息。
- `steward_judge_request` / `steward_judge_response`：中心请求 Edge 上的值守 Agent 生成一条可代发给 Worker 的回复；Edge 必须按新增 assistant 消息识别有效回复，允许连续多轮返回相同短文本。2.1.32 起中心默认等待 11 分钟，Edge 本地值守 Judge 执行窗口为 10 分钟；同一 `localAgentId` 已有 Judge in-flight 时，Edge 必须快速返回 `ok=false` 和 `Steward judge already running for this agent`，不得排队重复请求。2.1.33 起 Edge 必须比较最新 assistant 时间戳，避免固定分页内 assistant 数量不变时把 `继续` 等重复短回复误判为空。
- `memory_search_request` / `memory_search_response`：中心请求 Edge 基于当前 Worker 上下文检索本地记忆，只返回有限摘要。
- `exec-approvals` 转发和状态同步。
- permission request snapshot 同步。

记忆检索 Bridge 请求：

```json
{
  "type": "memory_search_request",
  "requestId": "uuid",
  "query": "Worker 当前等待确认上下文",
  "limit": 3
}
```

记忆检索 Bridge 响应：

```json
{
  "type": "memory_search_response",
  "requestId": "uuid",
  "ok": true,
  "source": "remote-bridge",
  "query": "Worker 当前等待确认上下文",
  "results": [
    {
      "source": "openclaw-sqlite",
      "agentName": "human-watch",
      "path": "human-watch/sop.md",
      "title": "human-watch/sop.md",
      "snippet": "小范围验证通过后，值守可以回复继续..."
    }
  ]
}
```

约束：

- `limit` 服务端和客户端均限制在 1-20，人工值守实际默认使用 3。
- 响应只包含摘要，不上传完整记忆库。
- Edge 不可用或超时时，中心可回退 `memory_fts` 文件记忆检索；两者都为空时不注入记忆上下文。

本地会话继续接口：

```http
POST /api/sessions/continue
```

用途：向本地 Worker 会话写入用户消息，使 CLI 继续执行。

## 8.1 可靠 Edge 消息接口

目标：将人工值守 assist、session continue、权限决策从“实时 Bridge RPC”升级为“可排队、可重试、可审计”的跨端消息。

核心接口：

```http
POST /api/edge/messages
POST /api/edge/messages/lease
POST /api/edge/messages/{id}/ack
POST /api/edge/messages/{id}/fail
POST /api/edge/messages/{id}/cancel
GET  /api/edge/messages
GET  /api/edge/messages/{id}
```

本地接口：

```http
POST /api/local/mailbox/drain
GET  /api/local/mailbox/status
```

关键约束：

- `POST /api/edge/messages/lease` 只能返回调用客户端自身 `client_id` 的消息。
- 同一 `session_ref.serial_key` 的 continue/assist 只能同时 lease 一条。
- `ack/fail` 必须带 `lease_owner`，防止过期执行结果覆盖新 lease。
- 人工值守 assist 响应应支持 `delivery.mode=queued|delivered|failed`。
- `human_watch_interventions` 必须记录 `message_id` 与 `correlation_id`，便于从人工值守审计回溯到可靠消息状态机。
- 详细接口以 `文档/04-程序设计/接口设计-人工值守-三端协同通信优化.md` 为准。

## 9. Gateway Exec Approval 转发

内部转发目标：

```http
POST http://{gatewayHost}:{gatewayPort}/api/exec-approvals/respond
```

请求体：

```json
{
  "id": "gateway-exec-approval-id",
  "action": "approve",
  "reason": "审批理由"
}
```

映射规则：

- `deny` 或 `ask_human` -> `deny`
- `always_allow` 或 `approve_always` -> `always_allow`
- 其他 approve -> `approve`

失败补偿：

```json
{
  "gateway_exec_forward": {
    "status": "failed",
    "exec_approval_id": "id",
    "action": "approve",
    "error": "message",
    "retryable": true
  }
}
```

## 11. 发布与更新接口

Docker 镜像：

```text
crpi-c9b9bml2ajb23n5d.cn-shenzhen.personal.cr.aliyuncs.com/1sheng/agentcenter:<version>
crpi-c9b9bml2ajb23n5d.cn-shenzhen.personal.cr.aliyuncs.com/1sheng/agentcenter:latest
```

客户端更新：

- 服务端镜像需要包含或指向 Edge runtime 和托盘产物。
- 托盘更新依赖 manifest 中的版本、下载地址、校验信息。
- 客户端显示版本应与服务端发布版本保持一致。
- 当 manifest 目标 runtime 版本高于本地版本，托盘必须通过下载接口获取新 zip，并在安装失败时返回明确错误；不得通过本地旧 Web 的 provision 接口复制旧 runtime。

## 12. 兼容性与废弃

- 2.0.4 不改变用户终端直接运行 Codex 的行为。
- MCP 注入只作用于托管 Codex 进程。
- 权限请求表为新增表，对旧数据向前兼容。
- 高风险自动批准能力暂不开放。
- 授权校验兼容用户中心当前结构 `license.entitlements/license.expiresAt` 和旧版顶层 `entitlements/expiresAt`。
