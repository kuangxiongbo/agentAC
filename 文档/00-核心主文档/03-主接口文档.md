本文档是 Agent 指挥仓的唯一主接口文档，覆盖 HTTP API、Bridge、本地接口、MCP 工具、配置和发布产物接口。

- `MC_USERCENTER_TLS_INSECURE=1`：仅对 `USER_CENTER_API_URL` 下的授权、租户和授权模型接口接受自签证书；默认关闭。
- 2.1.93 计划任务 JSON 新增必填 `goal_criteria: string[]`，其 ID 必须属于当前目标且整个计划必须覆盖全部目标成功标准；自动记忆提取失败写入 `memory_candidates_extraction_failed` 监督事件。
- 2.1.94 自动学习调度返回 `skipped_exhausted` 统计；同一完成目标自动提取失败默认最多 3 次，手动提取接口仍可显式重试。
- 2.1.95 `steward_judge_request.prompt` 在 Center 发送前保证不超过 6000 字符；超长上下文使用带 `[truncated]` 标记的头尾保留裁剪。
- 2.1.97 Center 记忆页调用 `GET /api/steward-memories?limit=100` 展示云端值守记忆；`GET /api/memory/sync` 仅用于本地 Work 节点摘要。
- 2.1.98 `POST /api/steward-memories/{id}/actions` 新增 `disable`/`restore` 语义，保留 `reject`/`approve` 兼容别名；自动和手工创建记忆默认进入 approved 生效态。
- 2.1.96 `expires_at: null` 表示无过期时间；审核动作显式传 null 时清除已有过期时间，不传字段时保持原值。

## 2. 接口总览

接口类型：

- HTTP API：Next.js route handlers。
- SSE/事件：`eventBus` 和 `/api/events`。
- Bridge RPC：中心与边缘同步、读 transcript、continue、exec approval、值守记忆检索。
- 可靠 Edge 消息：云端 Relay 与本地 Mailbox 接口，覆盖人工值守 assist、session continue、权限决策补偿。
- Bridge `agent_status` 事件必须包含 `id/name/role/status`，并应包含 `framework/parent_id/session_key`。中心端必须兼容旧客户端缺失可选字段的状态包，不得把已有 `framework/session_key` 覆盖为空。
- MCP 工具：托管 Codex 调用 Mission Control 的工具出口。
- 本地 CLI/配置：Codex 启动参数、MCP 环境变量。
- 发布接口：Docker 镜像标签、托盘更新清单、客户端下载元数据。
- 发布校验接口/脚本：`pnpm run verify:release-surfaces` 在发布前校验所有版本表面和下载资产。

## 3. 认证与授权

通用约定：

- `viewer` 可读取资源。
- `operator` 可创建、变更、审批。
- 变更类接口必须经过 mutation rate limit。
- 企业高级能力还需要授权平台 entitlement 控制。
- 授权业务 `appId` 固定为 `mission-control`，必须与用户中心 SKU 的 `schema_app_id` 和 Zitadel 应用实例的 `business_app_id` 完全一致；`agentCenter` 仅作为应用/实例展示名。
- 服务端在线校验用户中心 `/api/internal/verify-access`，请求包含 `app_id/client_id`、`subject`、OIDC 实例上下文和运行阶段。
- 在线校验明确返回 `unsubscribed`、`expired`、`app_instance_mismatch`、`user_not_found`、`no_tenant` 时，接口不得用本地离线授权覆盖。
- 只有在线校验错误 `error` 或用户中心不可达时，才允许使用本地离线授权作为降级缓存。

权限请求相关：

- `GET /api/permission-requests` 需要 `viewer`。
- `POST /api/permission-requests` 需要 `operator`。
- `GET /api/permission-requests/{id}` 需要 `viewer`。
- `POST /api/permission-requests/{id}/decision` 需要 `operator`。
- `POST /api/permission-requests/{id}/worker-human-reply` 用于 Worker 原会话收到人工回复后回填平台审批结果，必须记录审计并关闭等待状态。
- MCP 工具 `mc_create_watch_event` 在未传 `options` 时用于托管 Worker 主动请求值守回复；在传 `options` 时兼容创建结构化权限请求；`mc_record_worker_human_reply` 用于记录 Worker 原会话人工回复。
- Codex 进程级 MCP 注入参数 `mcp_servers.mission_control.env` 必须是 TOML map，例如 `{ MC_URL = "...", MC_MANAGED_SESSION = "1" }`；返回 JSON 字符串属于无效配置。
- `/api/sessions/continue` 返回 `accepted/remote/reply` 后，前端必须立即展示提交或送达反馈；真实 assistant 内容仍以 transcript 刷新结果为准。
- 可靠 Edge 消息 API 必须使用统一 `message_id/correlation_id/idempotency_key/lease/ack/fail` 模型；Bridge 离线不等同业务失败，支持 mailbox 的客户端应返回 `queued=true` 并在上线后补偿执行。

授权状态相关：

- `GET /api/auth/me`：返回当前用户和有效授权；每次调用强制刷新在线授权。
- `GET /api/license/status?refresh=1`：授权设置页强制刷新授权缓存并返回当前有效授权。
- `GET /api/license/schema-template`：导出当前产品授权模板，包含 `appId=mission-control`、`enableHumanWatch`、`enableLocalCliElevation`。
- `GET /api/local-cli/elevation-entitled`：本地 Web 调用中心校验本地 CLI 提权订阅。Edge 客户端应优先发送 `x-edge-enroll-token`，中心从 scoped token 解析用户/租户后在线校验 `enableLocalCliElevation`；普通 Web/API 访问仍走 `viewer` 鉴权。

发布与下载相关：

- `GET /api/edge/download-info`：返回托盘客户端下载信息，版本以 `public/edge-tray/manifest.json` 为准。
- `GET /api/edge/download-info` 除统一 `tray_version` 外，还必须返回 `tray_downloads[]`，每项包含 `platform`、`arch_label`、`download_url`、`available`，供下载页区分 Apple Silicon 与 Intel 包。
- 当托盘本地启动失败且 `5101` 被占用时，错误信息必须区分“E-Agent Edge 自身旧 runtime 占用”与“其他软件占用”。若是其他软件，占用诊断需返回 PID、进程名和工作目录，避免误导用户执行无效重试。
- 托盘停止或重启本机 Web 客户端时，内部实现必须以进程组为单位终止当前托管进程树，然后再执行端口占用诊断和 owned 进程回收。仅终止单个 child 句柄不视为完成停止。
- `GET /api/releases/edge-runtime-manifest`：返回 Edge runtime 更新清单，版本以 `public/edge-runtime/manifest.json` 为准。
- `/edge/download` 页面必须展示 manifest 中的客户端版本，不能使用手写旧版本号。
- `pnpm run verify:release-surfaces` 必须在 Docker 构建前通过；该脚本校验服务端、本地 Web、托盘、Tauri、manifest、release docs、主文档、下载包 SHA-256 和 runtime zip 静态资源。
- 已安装托盘客户端只会在 manifest `client_version` 高于本地 runtime 版本时替换 runtime；同版本重新打包不会触发已安装用户升级。
- `GET /api/status?action=health` 的 `version` 字段是托盘判断 5101 是否为当前 runtime 的依据；托盘不得仅凭 HTTP 200 沿用旧健康进程。
- 托盘 `setup-status` 事件和 `get_setup_status` 命令返回的状态可包含 `progress`、`detail`、`downloaded_bytes`、`total_bytes`，用于展示 runtime 下载和安装阶段。`progress` 为 0-100；未知总大小时前端应显示不确定进度动画和已下载大小。
- 版本不匹配错误必须使用普通字符串展示当前运行版本和目标版本，不得向 UI 暴露 Rust `Option` 调试格式。
- manifest 驱动的 Runtime 安装在托盘进程内必须是单写操作；并发调用等待同一安装锁，不得并行写入相同 `.zip.download`、解压目录或 Runtime 目标目录。对外仍使用既有 manifest/API，无新增 HTTP 字段。
- 下载包 SHA-256、候选 Runtime 版本和运行依赖必须在替换前校验；启用后复验失败时恢复旧目录并返回明确安装错误，禁止返回成功或留下空 Runtime。
- 2.1.68 起发布门禁必须把 Runtime ZIP 解压到干净临时目录，确认必需 Next compiled 文件，并实际启动 `server.js` 调用 `GET /api/status?action=health` 校验版本。本机 standalone fallback 只允许在候选目录完成同等校验后原子启用；安装后非 Runtime 错误不得降级覆盖已通过校验的目标版本。
- 2.1.69 起 Goal 监督初次分派和纠偏/retry 的 `session.continue.requested.payload` 新增 `execution_timeout_ms=1800000`。Edge 兼容 `executionTimeoutMs`，并将有效值夹紧到 `10000..7200000` 毫秒后传给本地 CLI 执行器；缺失时保留 180000 毫秒默认。
- 2.1.70 起 `.dockerignore` 必须包含 `!public/edge-runtime/client-runtime-<current>-darwin-aarch64.zip`。发布门禁将该路径与 Runtime manifest URL/SHA 作为同一制品契约验证；公网 ZIP 响应必须为实际 ZIP 且 SHA 与 manifest 完全一致。
- 2.1.71 起 `POST /api/supervision/goals/{goalId}/tasks/{taskId}/actions` 对 `blocked` Goal 接收 `retry_task` 或 `reassign_task` 时，会在同一事务内将 Goal 恢复为 `running`，记录 `goal_status_changed(decision=resume, actor_type=steward_agent)`，再创建 `session.continue.requested`。请求体和响应结构不变。
- 2.1.72 起 `GET /api/agents/{id}/tasks` 在 Work 在线时返回本地 `recent_tasks` 并合并云端监督任务；响应增加 `authority` 和 `local_live`。
- 2.1.72 起 `GET /api/agents/{id}/activity` 合并本地 Work 活动/任务里程碑与云端监督、邮箱和会话控制事件；每条记录带 `source`。
- 2.1.72 起 Bridge `agent_detail_response.agent` 可带 `recent_tasks[]`、`recent_activities[]`、`workspace_files`、`workspace_source`；任务/活动最多各 50 条，单文件内容最多 256 KiB。旧 Edge 客户端缺少这些字段时，中心必须兼容回退到云端控制记录。
- 2.1.73 起 `/api/agents/{id}`、`/tasks`、`/activity`、`/files`、`/soul`、`/memory` 接受历史云端镜像 ID；若其 `client_id + local_agent_id` 已存在 Bridge 索引，按实时索引查询并在别名集合中保留历史名称。响应结构不变。
- 2.1.74 起 `GET /api/agents/{id}` 对历史镜像 ID 在线返回 `source=bridge_index`、`bridge_online=true`、`detail_live=true` 及实时本地详情；离线返回同一索引的有界缓存，不再返回旧 `source=client` 主详情。
- 2.1.75 起 `GET /api/tasks` 聚合云端控制任务与当前 Workspace 在线 Edge 的本地任务。本地条目包含 `source=local_runtime`、`authority=local_runtime`、`local_task_id`、`bridge_client_id`、`client_label`，并使用稳定负数投影 `id`；云端条目包含 `source=cloud_control`。响应增加 `authority`、`local_live` 和 `projection.clients/errors`，旧 Edge 未宣告新能力时自动回退云端列表。
- `GET /api/status?action=dashboard` 的 `db.tasks` 使用与 `/api/tasks` 一致的去重投影统计，并增加 `authority/localLive/clients/errors`。
- 2.1.76 起 `GET /api/activities` 聚合云端控制事件和当前 Workspace 在线 Edge 的本地活动/会话里程碑。本地条目包含 `source=local_runtime`、`authority=local_runtime`、`local_activity_id`、`bridge_client_id`、`client_label` 和稳定负数 `id`；云端条目标记 `source=cloud`。响应增加 `authority`、`local_live`、`projection_clients/errors/truncated`。
- `GET /api/activities` 的 `type` 支持逗号分隔多值；`actor`、`entity_type`、`since`、`client_id`、`limit`、`offset` 同时作用于投影合并。`limit` 夹紧到 `1..500`，`offset` 不得为负。`stats=1` 或 `/stats` 的类型、Actor 和小时桶统计包含在线 Edge 快照。
- 2.1.77 Activity 页选择 `source=bridge_index` Agent 时，请求 `actor` 必须使用 Agent `config.original_name`；字段缺失时才回退 `name`。该规则只影响 UI 查询参数，不改变 `/api/activities` 的精确 actor 语义。
- 2.1.78 起 `GET /api/agents/{id}/diagnostics` 和 `/attribution` 对 Bridge Work Agent 返回 Edge 实时计算结果，并增加 `authority=local_runtime/local_live=true`；Edge 离线返回 `503` 及 `local_live=false`，不回退云端空库。
- 2.1.79 起 `GET /api/security-audit` 复用 60 秒基础设施扫描快照；安全修复和 Agent 扫描修复接口在写入后使用 `runSecurityScan({ force: true })` 即时复检。
- 2.1.80 起 `GET /api/search` 返回 `authority/local_live/local_errors`，本地结果增加 `source/client_id/local_entity_id/original_agent_name`；`POST /api/standup` 的报告增加 `sources`，并将 Edge Work 任务纳入状态、阻塞和逾期统计。
- 2.1.81 Bridge 连接替换使用 WebSocket close code `4001` 和 `Superseded by newer connection`；旧连接的待定 RPC 返回明确替换错误。
- 2.1.82 `POST /api/tasks/local-mutations`（operator）请求字段：`client_id`、正整数 `local_task_id`、`expected_updated_at`、`operation=update|delete`、必填 `idempotency_key`；update 的 `changes` 仅允许 `title/description/status/priority/assigned_to/due_date/estimated_hours/actual_hours/tags`。首次创建返回 `202 accepted=true + message_id/status=pending`，重复幂等请求返回原 `message_id` 和 `duplicate=true`。
- Edge 消息 `work.task.mutation.requested` 必须包含当前 Workspace 和操作者。Runtime 仅在消息 client 与本机身份一致、任务属于该 Workspace 且 `updated_at` 精确匹配时执行；成功 ACK result 返回 `operation/local_task_id/updated_at|deleted/applied_at`，失败返回稳定 `error_code`，其中版本冲突为 `TASK_VERSION_CONFLICT` 且 `retryable=false`。
- 2.1.83 `GET /api/tasks`、`GET /api/activities`、`GET /api/search`、`POST /api/standup` 和 Dashboard 状态在无实时 Edge 结果但存在有效快照时返回 `authority=local_snapshot`、`local_live=false`、`local_stale=true`。离线条目使用 `source/authority=local_snapshot`、`stale=true`、`snapshot_at=<unix seconds>`；客户端摘要增加 `live/stale/snapshot_at`。
- 同一请求中部分 Edge 在线时总 authority 可保持 `local_runtime|combined`，同时 `local_stale=true` 表示还合并了其他客户端旧快照。离线任务投影禁止编辑、拖拽和删除；重连后的实时条目恢复 `local_runtime` 及可靠写回能力。
- `GET /api/agents/evals?timeframe=hour|day|week|month` 在未传 `agent` 时返回 `{agents,overallConvergence,driftAlerts,authority}` 聚合结构；传 `agent` 时保持原单 Agent 契约。
- `GET /api/tokens?action=session-costs` 返回 `{sessions,timeframe}`，每条包含 `sessionId/model/inputTokens/outputTokens/totalTokens/totalCost/requestCount/firstSeen/lastSeen`。`stats/trends/agent-costs/task-costs/by-agent` 共用 Center 与 Edge 合并后的标准化明细。
- Tray 进程控制接口内部必须在同一生命周期锁内完成健康检查、端口归属判断和 spawn；并发调用只复用首个健康进程，不得向 `5101` 发起第二次监听。该变更不新增 HTTP 字段。
- macOS 客户端升级到 Tray 3.0.10 时会移除旧 `~/Library/LaunchAgents/work.1sheng.e-agent-edge.runtime.plist` 和 `~/.e-agent-edge/runtime-node.pid`；Edge 数据库、配置、Agent 和会话数据不删除。

本地会话接口性能约束：

- `GET /api/sessions` 不得因单个 Codex JSONL 大文件整文件读取而阻塞 5101 服务；大文件只能窗口读取。
- `GET /api/sessions/transcript?kind=codex-cli` 必须支持大 JSONL 分页读取并返回 `hasMoreOlder`、`nextOlderCursor`、`sourceSize`。
- `POST /api/sessions/continue` 和提权发送不能被会话列表扫描长时间阻塞；发布验证需覆盖普通发送和 `local_cli_elevated=true` 发送。
- `POST /api/sessions/continue` 返回 `{ ok: true, accepted: true }` 表示请求已入队，不代表 assistant 回复已经完成；前端必须释放发送按钮，并通过强制 transcript 刷新追踪后续回复。
- `GET /api/sessions/transcript` 返回的 assistant 可见文本是结束等待态的依据；如果当前发送基线之后已有 assistant 文本且无未完成工具调用，UI 必须停止计时并允许继续发送。
- 本地 CLI 提权 UI 通过会话级本地偏好保存选中状态；请求接口仍以每次发送体中的 `local_cli_elevated=true` 为准，避免 UI 状态和执行权限隐式耦合。

## 4. 通用约定

请求格式：

- JSON 请求体使用 `Content-Type: application/json`。
- 时间字段优先使用 Unix 秒。
- 错误响应格式：`{ "error": "message" }`。

状态：

- 权限请求状态：`pending`、`approved`、`denied`、`expired`、`cancelled`。
- 风险级别：`low`、`medium`、`high`、`critical`。
- 决策者类型：`human_user`、`steward_agent`、`system`。

## 5. 权限请求 API

### 5.1 创建权限请求

```http
POST /api/permission-requests
```

用途：Worker、MCP 或平台创建一个需要审批的权限请求。

权限：`operator`。

请求体：

```json
{
  "id": "optional-request-id",
  "client_id": "edge-client-id",
  "worker_local_agent_id": 123,
  "worker_name": "worker",
  "worker_session_id": "session-key",
  "steward_local_agent_id": 456,
  "steward_name": "watcher",
  "request_type": "local_cli_elevation",
  "title": "需要执行高风险命令",
  "prompt": "Worker 请求执行命令，请审批。",
  "risk": "medium",
  "options": [
    { "id": "approve_once", "label": "批准一次", "action": "approve" },
    { "id": "deny", "label": "拒绝", "action": "deny" }
  ],
  "context": {
    "command": "example",
    "gateway_exec_approval_id": "optional"
  },
  "expires_at": 1780000000
}
```

响应：

```json
{
  "request": {
    "id": "request-id",
    "status": "pending",
    "risk": "medium",
    "options": []
  }
}
```

错误：

- `400`：请求体无效、缺少 title/prompt/options。
- `401/403`：鉴权或角色不足。
- `429`：变更频率限制。

### 5.2 查询权限请求列表

```http
GET /api/permission-requests?status=pending&client_id=xxx&worker_local_agent_id=1&limit=50
```

用途：平台 UI 查询待审批或历史请求。

权限：`viewer`。

查询参数：

- `status`
- `client_id`
- `worker_local_agent_id`
- `steward_local_agent_id`
- `limit`

响应：

```json
{
  "requests": [],
  "count": 0
}
```

### 5.3 查询或等待单个权限请求

```http
GET /api/permission-requests/{id}
GET /api/permission-requests/{id}?wait=1&timeout_ms=30000
```

用途：MCP/Worker 查询或等待审批结果。

权限：`viewer`。

规则：

- `wait=1` 时等待请求从 `pending` 变为终态。
- `timeout_ms` 最小 1000。
- 超时返回 `504`。

### 5.4 提交审批决定

```http
POST /api/permission-requests/{id}/decision
```

用途：人类操作者、值守 Agent 或系统提交审批决定。

权限：`operator`。

请求体：

```json
{
  "optionId": "approve_once",
  "reason": "已确认命令风险可接受",
  "deciderType": "human_user",
  "deciderAgentId": "optional-agent-id"
}
```

规则：

- 请求必须处于 `pending`。
- `optionId` 必须存在于请求 options。
- `deciderType` 必须是 `human_user`、`steward_agent` 或 `system`。
- `steward_agent` 不能批准 `high` 或 `critical` 风险。
- 如果 context 包含 `gateway_exec_approval_id`，系统会尝试转发到 Gateway exec approval。

响应：

```json
{
  "request": {
    "id": "request-id",
    "status": "approved",
    "selected_option_id": "approve_once",
    "decider_type": "human_user"
  },
  "gatewayForward": {
    "status": "applied",
    "execApprovalId": "gateway-id"
  }
}
```

转发失败响应会带 `warning`，同时请求上下文写入 `gateway_exec_forward.status=failed`。

## 8. Bridge 与本地接口

Bridge 负责中心和边缘之间的同步与远程执行。当前发布涉及：

- WebSocket 连接必须通过 `Authorization: Bearer <token>` 或 `x-api-key` 提供 Bridge token。
- 中心 Bridge token 解析顺序为显式 Bridge token、Edge Bridge token、服务端 API key、旧 `gateway.token` 兼容值。
- 未配置 token 时默认拒绝连接；只有显式 `MC_BRIDGE_ALLOW_ANONYMOUS=1` 才允许匿名桥接。
- Agent/session 同步。
- transcript 读取。
- `sessions/continue` 写入 user 消息。
- `steward_judge_request` / `steward_judge_response`：中心请求 Edge 上的值守 Agent 生成一条可代发给 Worker 的回复；Edge 必须按新增 assistant 消息识别有效回复，允许连续多轮返回相同短文本。2.1.32 起中心默认等待 11 分钟，Edge 本地值守 Judge 执行窗口为 10 分钟；同一 `localAgentId` 已有 Judge in-flight 时，Edge 必须快速返回 `ok=false` 和 `Steward judge already running for this agent`，不得排队重复请求。2.1.33 起 Edge 必须比较最新 assistant 时间戳，避免固定分页内 assistant 数量不变时把 `继续` 等重复短回复误判为空。2.1.37 起 Edge 必须拒绝明显 CLI/模型环境错误文本，中心记录 `steward_judge_failed`，不得将错误文本通过 `session_continue` 自动代发。2.1.39 起托盘 bootstrap 周期同步不得因非 Bridge 关键字段变化触发 `restartRemoteBridge()`，避免中心发起 transcript / continue RPC 时连接被本地重启打断。
- `memory_search_request` / `memory_search_response`：中心请求 Edge 基于当前 Worker 上下文检索本地记忆，只返回有限摘要。
- `task_snapshot_request` / `task_snapshot_response`：中心仅向宣告 `task_snapshot` capability 的 Edge 发起请求。请求包含 `requestId` 和夹紧到 `1..1000` 的 `limit`；响应包含 `ok`、`tasks[]`、`total`、`byStatus`、`truncated`、`source`。任务的 `tags/metadata` 必须为已解析 JSON，描述最多返回 16000 字符。中心请求默认 5 秒超时，单客户端失败不阻断其他客户端或云端数据。
- `task_snapshot_changed`：Edge 任务变化后的轻量失效事件，不携带任务正文。Center 忽略消息中自报的 Client 身份，使用 WebSocket 连接已验证的 `clientId`，清缓存后向 UI 广播 `task.projection_changed`。
- `activity_snapshot_request` / `activity_snapshot_response`：中心仅向宣告 `activity_snapshot` capability 的 Edge 发起请求。请求包含 `requestId` 和夹紧到 `1..1000` 的 `limit`；响应包含 `ok`、`activities[]`、`total`、`truncated`、`source`。活动 `data` 必须为已解析对象；CLI 会话以 `session_activity` 返回 `session_id/session_key/session_kind/runtime_group/active/model/working_dir/last_user_prompt`。中心默认等待 5 秒，单客户端失败降级且不得中断全局活动接口。
- `activity_snapshot_changed`：Edge 对活动和会话变化使用 1 秒节流发送的无正文失效事件。Center 使用当前 WebSocket 已验证身份解析 Workspace，清理活动快照并通过 SSE 广播 `activity.projection_changed`；旧 Edge 未宣告 capability 时保持云端活动兼容视图。
- `agent_metrics_request` / `agent_metrics_response`：请求 `metric=diagnostics|attribution|evals|tokens`。前两者要求 `localAgentId`、`hours(1..720)` 和可选 `sections[]`；`evals` 接受 `timeframe`；`tokens` 返回标准化 `records[]`。响应包含 `ok/metric/metrics/source=local_runtime`，默认 12 秒超时，失败不影响云端权威数据。
- `exec-approvals` 转发和状态同步。
- permission request snapshot 同步。

记忆检索 Bridge 请求：

```json
{
  "type": "memory_search_request",
  "requestId": "uuid",
  "query": "Worker 当前等待确认上下文",
  "limit": 3
}
```

记忆检索 Bridge 响应：

```json
{
  "type": "memory_search_response",
  "requestId": "uuid",
  "ok": true,
  "source": "remote-bridge",
  "query": "Worker 当前等待确认上下文",
  "results": [
    {
      "source": "openclaw-sqlite",
      "agentName": "human-watch",
      "path": "human-watch/sop.md",
      "title": "human-watch/sop.md",
      "snippet": "小范围验证通过后，值守可以回复继续..."
    }
  ]
}
```

约束：

- `limit` 服务端和客户端均限制在 1-20，人工值守实际默认使用 3。
- 响应只包含摘要，不上传完整记忆库。
- Edge 不可用或超时时，中心可回退 `memory_fts` 文件记忆检索；两者都为空时不注入记忆上下文。

## 8.1 可靠 Edge 消息接口

目标：将人工值守 assist、session continue、权限决策从“实时 Bridge RPC”升级为“可排队、可重试、可审计”的跨端消息。

2.1.67 完成语义：`POST /api/edge/messages/{id}/ack` 中 `result.delivered=true` 表示对应 Worker CLI 本轮已完成，不再表示仅已调用本地 enqueue。Edge 使用 completion-aware 串行执行入口；CLI 抛错时调用 `/fail`，`error_message` 保存实际异常。`result.reply`/`worker_reply` 可用于审计摘要，完整过程仍从 transcript 读取。

核心接口：

```http
POST /api/edge/messages
POST /api/edge/messages/lease
POST /api/edge/messages/{id}/ack
POST /api/edge/messages/{id}/fail
POST /api/edge/messages/{id}/cancel
GET  /api/edge/messages
GET  /api/edge/messages/{id}
```

本地接口：

```http
POST /api/local/mailbox/drain
GET  /api/local/mailbox/status
```

关键约束：

- `POST /api/edge/messages/lease` 只能返回调用客户端自身 `client_id` 的消息。
- 同一 `session_ref.serial_key` 的 continue/assist 只能同时 lease 一条。
- `ack/fail` 必须带 `lease_owner`，防止过期执行结果覆盖新 lease。
- 人工值守 assist 响应应支持 `delivery.mode=queued|delivered|failed`。
- `human_watch_interventions` 必须记录 `message_id` 与 `correlation_id`，便于从人工值守审计回溯到可靠消息状态机。
- 详细接口以 `文档/04-程序设计/接口设计-人工值守-三端协同通信优化.md` 为准。

## 13. 目标监督与记忆接口

### 13.1 值守目标监督接口（2.1.45）

- `GET/POST /api/supervision/goals`：查询或创建目标。
- `GET/PATCH /api/supervision/goals/{id}`：返回 Goal、关联任务和监督事件，或按 version 乐观锁更新。
- `GET /api/supervision/goals/{id}` 的任务记录包含 `assigned_agent_id`、`assigned_session_id`、`client_id`、`session_kind`、`error_message`、`updated_at`，供中心 UI 定位远程执行会话和判断停滞。
- `POST /api/supervision/goals/{id}/plan`：值守生成或人工提交结构化计划。
- `POST /api/supervision/goals/{id}/actions`：批准/拒绝计划、暂停、恢复、取消、重规划和验收状态迁移。
- `POST /api/supervision/goals/{id}/dispatch`：幂等创建任务、匹配 Worker，并写入可靠 `session.continue.requested`。
- dispatch 以实时 Bridge 在线状态判断节点可达；带专用会话的 offline/sleeping Worker 可恢复但降权。阻塞事件的 `action.match_diagnostics` 返回候选数量和逐 Agent rejected reason。
- 带 `metadata.goal_id` 的任务不进入旧任务 auto-route；其 `assigned_to`、`assigned_session_id` 和可靠 `message_id` 只能由 Goal Dispatcher 写入。
- 旧任务调度器的 auto-route、assigned dispatch、stale requeue 和 Aegis review 都必须对 `metadata.goal_id` 执行硬隔离；auto-route 的状态写入必须带同样条件的 compare-and-set。
- `POST /api/supervision/goals/{id}/tasks/{taskId}/actions`：进度追问、纠偏、重试、换 Worker、重规划或转人工。
- `POST /api/supervision/goals/{id}/verify`：按独立证据逐条验收成功标准。
- 所有变更接口需要 operator；读取需要 viewer；租户隔离、幂等键、风险审批和 Goal 预算由中心强制执行。

### 13.2 Worker 中心 Goal 接口（2.1.46）

- `GET /api/supervision/worker-goals/{id}`：返回中心权威 Goal、关联任务和监督事件；Edge 同路径使用 `gateway.token` 代理到中心。
- `POST /api/supervision/worker-tasks/{taskId}/complete`：提交 `goal_id`、Worker/session、outcome、resolution 和 evidence。中心校验 Goal 归属、任务状态及绑定身份后写入 `goal_task_worker_completed`，不经过 legacy Aegis。
- MCP `mc_get_supervision_goal` 与 `mc_complete_supervision_task` 固定调用上述本机同源路径；Worker 不直接持有中心密钥。完成工具中的 Worker ID 和 session ID 只能由平台托管进程环境注入，不对工具参数暴露，也不接受 Worker 输出覆盖。
- 2.1.47 中心任务队列和 scheduler 的隔离合约为：`metadata.goal_id IS NULL` 且不存在对应 `supervision_goal_tasks.task_id`。任一条件表明为监督任务时，legacy 路径必须跳过。
- 2.1.48 `session.continue.requested.payload` 对监督 Worker 增加 `worker_local_agent_id`；Edge 必须把该字段转为受管进程环境 `MC_AGENT_ID`，并以 `session_id` 作为 `MC_WORKER_SESSION_ID`，工具调用参数不得覆盖这两个身份。
- 2.1.49 MCP `tools/list` 必须为 `mc_get_supervision_goal` 返回 `readOnlyHint=true`，为 `mc_complete_supervision_task` 返回 `readOnlyHint=false`、`destructiveHint=false`、`idempotentHint=true`、`openWorldHint=false`；依赖未完成的 task 在 API 中仍为 `inbox`，但 `assigned_to` 内部值为专用 hold assignee，仅 Goal Dispatcher 可释放。
- 2.1.50 `GET /api/supervision/worker-goals/{id}` 返回 `schema=2`：`goal` 仅包含身份、状态、版本、Worker/值守绑定、budget/usage；`tasks` 全量返回 task ID、logical key、dependencies、status/outcome、Worker/session、重试计数及有界 resolution/error 摘要；`event_summary` 返回总数、按类型计数、latest ID 和 truncated；`events` 只返回最近 100 条紧凑事件。不再返回原始 metadata、evidence_json 和 action_json。
- 2.1.50 MCP `mc_get_task` 声明 `readOnlyHint=true`、`destructiveHint=false`、`idempotentHint=true`、`openWorldHint=false`，作为 Worker 查询单任务的非交互兼容回退。legacy scheduler 的调度契约同时排除 `created_by='goal-supervisor'`、`metadata.goal_id` 和 `supervision_goal_tasks.task_id`，并在所有状态写回重复该条件。
- 2.1.51 MCP `mc_continue_session` 声明 `readOnlyHint=false`、`destructiveHint=false`、`idempotentHint=true`、`openWorldHint=false`。中心 `/api/sessions/continue` 按 client、session、kind 和 prompt 指纹生成幂等键，重复续话返回同一可靠消息，不重复注入 Worker。
- 2.1.52 MCP `mc_continue_session` 在受管进程内向 Edge `/api/sessions/continue` 附加隐藏 `_managed_by_platform`、`_worker_local_agent_id`、`_worker_session_id`；Edge 仅在 `x-api-key` 存在且 session 精确匹配时转为 `managedByPlatform` 执行选项。`mc_list_sessions`、`mc_session_transcript` 声明 read-only/non-destructive/idempotent/closed-world；`mc_control_session` 因包含 pause/terminate 不降低审批。
- 2.1.53 `retry_task` / `correct_direction` 生成的 `session.continue.requested.payload` 增加 `worker_local_agent_id`，与初始 Goal dispatch 消息对齐；Edge mailbox 将其转为 `enqueueLocalSessionPrompt(..., { managedByPlatform: true, agent: { id }, workerSessionId, sessionKind })`。
- 2.1.54 `GET /api/supervision/worker-goals/{id}` 返回 schema 3。`event_summary.by_type` 是全历史完整计数，`events` 最多返回最近 20 条，`history_windowed` 表示窗口化，`payload_bytes` 提供序列化体积，`truncated` 保留为传输完整性标志。
- 2.1.54 Worker Goal 响应限制 objective、resolution/error summary 和 event reason 长度；三任务生产验证响应应小于 10KB，避免 MCP 客户端出现展示层 `...truncated...`。
- 2.1.55 Agent `config.mc_session_project_path` 是本地 CLI 恢复执行的权威 cwd。`executeBoundLocalAgentPrompt` 和 mailbox 续话必须把该目录传给 `codex exec resume`；目录不存在时按现有安全回退处理，不得静默替换为 Runtime 目录。
- 2.1.56 `session.continue.requested.payload.worker_local_agent_id` 不仅用于注入 `MC_AGENT_ID`，也用于 Edge 在排队前刷新完整 Agent 配置。`enqueueLocalSessionPrompt(..., { agent: { id } })` 必须解析并传递持久化项目 cwd，且生命周期事件保留该 Agent ID。
- 2.1.57 Verifier 的 `independent_evidence` 增加 `task:{taskId}:managed-completion:{eventId}` 引用，value 包含中心受管完成证明、结构化 evidence 和 Worker/session assignment。该引用只来源于 `goal_task_worker_completed`，不能由普通任务 resolution 伪造。
- 2.1.58 `steward_judge_request.prompt` 在 Goal 验收路径使用 5900 字符上限，低于 Edge 接口的 6000 字符拒绝阈值。请求必须包含证据索引；超长详情按字段压缩，不能仅通过截断丢失全部 evidence ref。
- 2.1.59 `PATCH /api/human-watch/bindings/{id}` 设置 `enabled=true` 或更新规则后会刷新 `updated_at`；编排器以该时间作为 `auto_stop.max_runtime_seconds` 的新周期起点。
- `/api/tasks/queue` 的 current、capacity 与 atomic claim 查询均排除 `metadata.goal_id`。
- 2.1.84 自动值守代答创建 `session.continue.requested`，payload 携带 `human_watch_binding_id/fingerprint/event_id/rules_hit`；ACK 回调将结果关联写入 `human_watch_interventions` 和 `human_watch_events`。
- 2.1.85 值守 judge 输出契约为 `{"action":"reply|ask_worker|escalate_human","reply":"...","reason":"...","risk":"normal|high|critical"}`。纯文本输出作为兼容 `reply/normal`。Center 安全复核或 judge 转人工时不创建 `session.continue.requested`，事件保持 `visible`，并以 `dangerous_action_requires_human` 或 `steward_escalated_human` 记录跳过原因。
- 2.1.86 active watch event dedupe key 为 `transcript:{binding_id}:{worker_session_id}:{fingerprint}`；存在未终态事件时编排器不重复 judge/send。Edge Agent POST 仍立即返回 `session_provisioning=true`，后台初始化完成后通过 Agent/session 同步更新。
- 2.1.87 `GET /api/human-watch/interventions` 保持原干预字段，并为每行新增 `evidence`：`watch_event_id/status/priority`、`message_id/correlation_id`、`mailbox_status/attempt_count`、`queued_at/updated_at/completed_at`、`delivery_result/worker_reply`、`last_error_code/last_error_message` 及三个派生耗时。无关联历史记录返回对应 null，不改变旧字段语义。
- 2.1.88 不新增外部接口或数据迁移；现有 binding `rules_override.auto_stop.max_runtime_seconds` 在 Edge Bridge 离线时仍由中心轮询执行，到期后沿用既有 binding 更新与 `auto_stop` 干预记录语义。
- 2.1.89 内部 Bridge `steward_judge_request` 新增可选 `fastPrompt`，旧 Edge 忽略该字段并继续使用 `prompt`。`fastPrompt` 不超过 1600 字符，包含结构化输出约束、风险规则、近期上下文、受控记忆和会话；外部 HTTP API、数据库 schema 与可靠消息协议不变。
- 2.1.90 仅收紧 `fastPrompt` 语义约束，不改变 Bridge 字段、HTTP API、数据库 schema 或 mailbox 协议。
- 2.1.91 `mc_create_watch_event` 声明 non-destructive/idempotent/closed-world annotations；`POST /api/human-watch/assist` 的 `reply` 为最终纯文本，不再返回可被续写的原始 judge JSON。

### 13.3 值守记忆接口（2.1.43）

- `GET/POST /api/steward-memories`：查询或创建记忆；默认创建为 approved（生效）。
- `POST /api/steward-memories/{id}/actions`：disable、restore、correct、expire、supersede；approve/reject 作为兼容别名。
- `POST /api/steward-memories/search`：只返回 approved、作用域匹配且未过期记忆，并创建 usage。
- `POST /api/steward-memories/usage/{id}/outcome`：记录 adopted 与 helpful/harmful/irrelevant，调整置信度。
- `POST /api/supervision/goals/{id}/memories/extract`：完成 Goal 后提取并激活记忆，按 Goal 幂等；重复证据不会复活已停用记忆。

## 15. 2.1.60 Workspace 与分发契约

- `audit_log.workspace_id` 必填；`GET /api/audit`、`GET /api/export?type=audit`、全局搜索、状态统计、归因和清理只能操作当前 Workspace。
- `PUT /api/workspaces/{id}` 接受 `brand` 和 `isolation=shared|strict`；非法 isolation 返回 400。
- `/api/sessions/continue` 和 `/api/sessions/transcript` 在远程模式校验 `client_id/session_id/session_kind` 属于当前 Workspace；归属不匹配返回 403。Edge 托管本地续话还校验 `local_agent_id`。
- `POST /api/permission-requests` 校验 Workspace/Tenant、Edge client 和 Human Watch binding 归属；跨域引用返回 400。
- `session.continue.requested.payload` 可包含 `dispatch_allowed_tools`、`dispatch_max_budget_usd`、`dispatch_cwd`。Edge 必须与 Agent 配置求交集/最小值，不能扩大权限。
- 根发布门禁：`node scripts/check-workflow-action-pins.mjs` 与 `node scripts/check-artifact-boundaries.mjs`；任一失败不得推送镜像。
- Bridge `agents_list/agent_status` 和 Gateway POST Agent 注册按当前 Client/User Workspace 执行 `ON CONFLICT(name, workspace_id)`；迁移 071 后不再接受 `ON CONFLICT(name)`。
