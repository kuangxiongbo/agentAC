# 框架设计-通用智能体中枢平台

## 1. 设计目标

通过统一的中心端与边缘端架构，把多类智能体纳入同一套可观测与可扩展体系。

## 2. 总体架构

### 2.1 部署形态

1. 中心服务端：部署 `mission-control`，对外提供统一控制台、API、数据库与桥接接收能力。
2. 客户端节点：部署 `mission-control-client`，对内做本机探测，对外向中心端同步。
3. 本机运行时：包括 OpenClaw、Claude Code、Codex CLI、Hermes，以及未来的 Cursor、OpenCode、Antigravity。

### 2.2 中心化与去中心化关系

1. 执行保持在边缘节点，本地进程和会话不迁移到中心端运行。
2. 监控、聚合、视图、任务协调、跨节点观察集中在服务端。

## 3. 模块边界

### 3.1 中心服务端模块

1. UI 与 API 层：负责展示、查询、管理、控制。
2. 数据层：统一保存 Agent、Task、Session、Audit 等数据。
3. Bridge Server：负责接收来自客户端的连接和状态消息。
4. Adapter 层：负责统一外部框架接入协议。

### 3.2 客户端模块

1. 本地数据库：缓存本机探测到的 Agent 和 Session。
2. Local Sync：扫描本机 Agent 定义目录。
3. Runtime Detection：检测本机运行时安装状态。
4. Session Scanner：扫描 Claude/Codex/Hermes/OpenClaw 会话。
5. Remote Bridge：向中心端发送 Agent 状态和事件。

## 4. 关键数据流

### 4.1 Agent 定义同步流

1. 客户端扫描本机目录。
2. 客户端将扫描结果写入本地数据库。
3. Remote Bridge 读取本地 Agent 清单。
4. 中心端接收并以 `source=bridge` 写入中心数据库。

### 4.2 Session 聚合同步流

1. 客户端分别扫描 OpenClaw Gateway、Claude、Codex、Hermes 会话。
2. 客户端在本地统一为 sessions 视图。
3. 中心端通过桥接和后续能力扩展进行聚合展示。

### 4.3 任务下发流

1. 中心端创建或路由任务。
2. 中心端通过桥接向客户端下发任务。
3. 客户端在本地创建任务或转交给本地 Agent。
4. 客户端再将任务状态回传中心端。

## 5. 统一数据模型

Agent 核心统一字段：

1. `id`
2. `name`
3. `role`
4. `status`
5. `source`
6. `node_id`
7. `framework`
8. `parent_id`
9. `last_seen`
10. `config`

## 6. 框架分层策略

### 6.1 原生网关型

代表：OpenClaw。

特点：

1. 具备工作区与网关概念。
2. 存在 Provision 与网关同步能力。
3. 需要保留兼容，但逐步弱化系统强绑定。

### 6.2 本机会话型

代表：Claude Code、Codex CLI、Hermes。

特点：

1. 重点在本地安装检测与会话扫描。
2. 通常不需要走 OpenClaw 风格 Provision。
3. 需要统一进入 Session 与 Agent 可观测体系。

### 6.3 外部适配器型

代表：generic、langgraph、crewai、autogen、claude-sdk。

特点：

1. 通过统一 API 接入。
2. 关注 register、heartbeat、report、assignments、disconnect 等协议动作。

## 7. 扩展原则

1. 新增框架时优先增加独立 detector、scanner 或 adapter，不直接把逻辑塞进通用分支。
2. 桥接消息必须继续沿用统一 payload 思路，至少保持 `name`、`role`、`status`、`framework`、`parent_id`、`node_id` 能传递。
3. UI 层展示按统一 Agent 模型构建，不为单一框架写死显示结构。

## 8. 当前架构风险

1. 服务端与客户端仍共享大量历史代码结构，角色分离仍可继续强化。
2. OpenClaw 仍在部分路径中是隐含默认框架。
3. 新框架探测器尚未标准化为统一插件接口。

## 9. 下一步架构演进

1. 提炼统一 runtime detector 接口。
2. 提炼统一 session scanner 接口。
3. 进一步明确“纯中心模式”和“边缘模式”的启动差异。
4. 逐步把 OpenClaw 从系统默认假设改成普通框架之一。
