# 接口设计-值守目标监督与受控记忆

## 1. 约定

- REST 前缀：`/api/supervision`。
- 所有写接口要求 operator；高风险决策要求 admin 或权限请求批准。
- 所有写接口支持 `Idempotency-Key`。
- 时间使用 Unix 秒；ID 使用 UUID 字符串。
- 所有响应按 workspace/tenant 隔离。
- 模型结构化输出不作为公开 API，必须先通过服务端 schema 校验。

## 2. Goal API

### 2.1 `POST /api/supervision/goals`

创建目标。

请求：

```json
{
  "steward_agent_id": 7,
  "title": "修复并验证支付回调问题",
  "objective": "定位回调丢失原因，修复后完成自动化和生产灰度验证",
  "success_criteria": [
    { "id": "sc-1", "text": "回调重放测试 100% 通过", "evidence_type": "test" },
    { "id": "sc-2", "text": "生产灰度 30 分钟无新增错误", "evidence_type": "metric" }
  ],
  "constraints": ["不得删除生产数据", "高风险变更必须人工确认"],
  "allowed_worker_ids": [6, 10],
  "priority": "high",
  "deadline_at": 1784088000,
  "budget": {
    "max_tasks": 8,
    "max_parallel_workers": 2,
    "max_retries_per_task": 3,
    "max_replans": 5,
    "max_runtime_seconds": 86400,
    "max_model_calls": 100
  },
  "requires_plan_approval": true
}
```

响应 `201`：

```json
{
  "goal": {
    "id": "goal_uuid",
    "status": "planning",
    "version": 1
  },
  "correlation_id": "goal:goal_uuid:create"
}
```

### 2.2 `GET /api/supervision/goals`

过滤参数：`status`、`steward_agent_id`、`assigned_worker_id`、`limit`、`offset`。

### 2.3 `GET /api/supervision/goals/{goal_id}`

返回 Goal、当前计划、任务摘要、预算使用、最近事件、人工决策和验收摘要。

### 2.4 `PATCH /api/supervision/goals/{goal_id}`

允许修改 title、criteria、constraints、deadline、budget 和 allowed workers。请求必须带 `version`，运行中修改成功标准会触发重规划。

### 2.5 `POST /api/supervision/goals/{goal_id}/actions`

请求：

```json
{
  "action": "approve_plan",
  "plan_version": 1,
  "reason": "计划范围符合预期"
}
```

支持：`approve_plan`、`reject_plan`、`pause`、`resume`、`cancel`、`request_replan`、`accept_result`、`reject_result`。

## 3. Plan API

### 3.1 `POST /api/supervision/goals/{goal_id}/plan`

触发计划生成或重规划。运行中调用必须提供 `reason` 和 `source_event_id`。

### 3.2 `GET /api/supervision/goals/{goal_id}/plans`

返回所有不可变版本及状态。

计划结构：

```json
{
  "version": 1,
  "summary": "先诊断，再修复和验证",
  "tasks": [
    {
      "logical_key": "diagnose",
      "title": "定位回调丢失原因",
      "description": "检查日志、队列和幂等记录",
      "dependencies": [],
      "required_capabilities": ["backend", "observability"],
      "preferred_framework": "codex-cli",
      "acceptance_criteria": ["输出可复现根因及证据"],
      "estimated_minutes": 30,
      "risk": "low"
    }
  ]
}
```

服务端拒绝：任务超过预算、依赖有环、缺少验收、风险越权、Worker 类型非法。

## 4. Task 与分派 API

### 4.1 `POST /api/supervision/goals/{goal_id}/dispatch`

将已批准计划创建为现有 tasks 并分派。重复调用使用 logical key 幂等。

响应包含 task ID、ticket ref、Worker、匹配评分和分派理由。

### 4.2 `POST /api/supervision/goals/{goal_id}/tasks/{task_id}/actions`

支持：

- `retry`
- `reassign`
- `request_progress`
- `correct_direction`
- `create_followup`
- `mark_blocked`
- `request_human_decision`

请求：

```json
{
  "action": "correct_direction",
  "reason": "当前实现修改了目标范围外模块",
  "message": "停止修改认证模块，只处理支付回调幂等逻辑。",
  "source_event_id": 1234
}
```

## 5. 监督与事件 API

### 5.1 `GET /api/supervision/goals/{goal_id}/events`

参数：`event_type`、`task_id`、`since`、`limit`。

事件示例：

```json
{
  "id": 1234,
  "goal_id": "goal_uuid",
  "task_id": 88,
  "event_type": "worker_direction_deviation",
  "actor_type": "steward",
  "decision": "correct_direction",
  "reason": "修改超出目标范围",
  "evidence": [{ "type": "transcript", "ref": "codex-cli:session:line:42" }],
  "message_id": "edge_message_uuid",
  "correlation_id": "goal:goal_uuid:task:88:correction:1",
  "created_at": 1784000000
}
```

### 5.2 `POST /api/supervision/goals/{goal_id}/evaluate`

内部/operator 调试接口，触发一次监督评估。参数 `dry_run=true` 时只返回建议，不执行动作。

响应：

```json
{
  "snapshot_version": 12,
  "decision": {
    "action": "request_progress",
    "task_id": 88,
    "risk": "low",
    "reason": "20 分钟无状态和 transcript 更新"
  },
  "executed": false
}
```

### 5.3 `GET /api/supervision/health`

返回 Goal supervisor backlog、lease、失败率、平均纠偏延迟和 stalled goals。人工值守基础指标继续使用 `GET /api/human-watch/health`。

## 6. 验收 API

### 6.1 `POST /api/supervision/goals/{goal_id}/verify`

进入或重跑验收。

响应：

```json
{
  "verification_id": "verify_uuid",
  "status": "failed",
  "criteria": [
    { "id": "sc-1", "status": "pass", "evidence_refs": ["test:run-1"] },
    { "id": "sc-2", "status": "unknown", "evidence_refs": [], "reason": "缺少灰度监控窗口" }
  ],
  "followup_tasks": [{ "logical_key": "observe-production" }]
}
```

### 6.2 `GET /api/supervision/goals/{goal_id}/report`

返回最终报告 JSON；后续可导出 Markdown/PDF。

## 7. Memory API

### 7.1 `GET /api/steward-memories`

过滤：`status`、`category`、`scope_type`、`scope_id`、`query`。

### 7.2 `POST /api/steward-memories`

允许 operator 手工创建生效记忆。Goal/Intervention outcome 使用同一底层能力自动提炼，校验通过后默认为 `approved`（生效）。

```json
{
  "category": "preference",
  "scope_type": "user",
  "scope_id": "2",
  "content": "发布前先完成生产小范围验证，再扩大范围",
  "source_refs": ["goal:goal_uuid", "event:1234"],
  "confidence": 0.72,
  "expires_at": null
}
```

### 7.3 `POST /api/steward-memories/{memory_id}/actions`

```json
{
  "action": "disable"
}
```

支持 `disable`、`restore`、`correct`、`expire`、`supersede`；保留 `approve`、`reject` 作为兼容别名。`disable` 后记忆立即退出检索，`restore` 后重新生效。

### 7.4 `POST /api/steward-memories/search`

内部检索接口：

```json
{
  "query": "生产发布验证流程",
  "goal_id": "goal_uuid",
  "categories": ["preference", "procedure", "fact"],
  "limit": 5,
  "max_chars": 2000
}
```

只返回 `approved`（生效）且作用域匹配的记忆，并创建 usage 记录。

### 7.5 `POST /api/steward-memories/usage/{usage_id}/outcome`

记录 `adopted`、`helpful`、`harmful`、`irrelevant` 和结果分数，用于置信度调整。

## 8. Bridge 与可靠消息扩展

新增消息类型：

| 类型 | 方向 | 说明 |
|------|------|------|
| `steward.goal.plan.requested` | cloud_to_edge | 请求值守 Goal Session 生成结构化计划 |
| `steward.goal.evaluate.requested` | cloud_to_edge | 请求监督评估和纠偏建议 |
| `steward.goal.verify.requested` | cloud_to_edge | 请求独立验收建议 |
| `worker.task.notify.requested` | cloud_to_edge | 通知 Worker 新任务或任务更新 |
| `session.continue.requested` | cloud_to_edge | 复用现有通道向 Worker 纠偏/追问 |

统一 payload 必须带：`goal_id`、`plan_version`、`correlation_id`、`schema_version`。模型响应必须包含 `response_schema_version`。

## 9. 内部结构化输出

### 9.1 `SupervisorDecision`

```json
{
  "action": "correct_direction",
  "task_logical_key": "implement-fix",
  "message": "只修改回调幂等模块，保持认证模块不变。",
  "reason": "当前 diff 超出目标约束",
  "risk": "low",
  "evidence_refs": ["transcript:...", "task:..."],
  "expected_result": "Worker 回到指定范围并提交测试",
  "requires_human": false
}
```

中心拒绝模型返回的未知 action、缺少证据、风险不匹配或超预算动作。

## 10. 错误码

| 错误码 | 含义 |
|--------|------|
| `GOAL_STATE_CONFLICT` | Goal version 或状态不允许当前操作 |
| `PLAN_SCHEMA_INVALID` | 计划结构不合法 |
| `PLAN_DEPENDENCY_CYCLE` | 任务依赖成环 |
| `WORKER_NOT_ELIGIBLE` | Worker 类型、能力、节点或状态不满足 |
| `GOAL_BUDGET_EXCEEDED` | 任务、时间、调用或成本超限 |
| `GOAL_LEASE_BUSY` | 另一个监督实例正在处理 |
| `SUPERVISOR_DECISION_REJECTED` | 建议违反策略或证据不足 |
| `HUMAN_APPROVAL_REQUIRED` | 当前动作必须人工确认 |
| `MEMORY_SCOPE_DENIED` | 记忆作用域不允许访问 |
| `MEMORY_REVIEW_REQUIRED` | 候选未批准，不能用于长期判断 |

## 11. 幂等和并发

1. 创建 Goal：调用方 Idempotency-Key 唯一。
2. 创建任务：`goal_id + plan_version + logical_task_key` 唯一。
3. 纠偏动作：`goal_id + source_event_id + action` 唯一。
4. Goal 更新使用 version 乐观锁。
5. Supervisor 使用 goal lease，默认 120 秒并可续租。
6. Worker session continue 使用现有 serial inbox。

## 12. 验证要求

1. 服务层状态机、DAG、预算、权限、幂等单测。
2. API 鉴权和跨租户隔离测试。
3. Bridge 离线、重试、重复 ack、lease 超时测试。
4. 多 Worker 任务依赖和重规划测试。
5. 记忆候选未批准不可检索、冲突 supersede、过期测试。
6. 真实 Goal 从创建到 completed 的 E2E 证据。
