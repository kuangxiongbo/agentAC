# 短视频场景清单-通用智能体中枢平台

## 1. 文档定位

本文件用于沉淀 E-AgentCenter / Mission Control 的短视频宣传场景，不按功能清单讲产品，而按真实生活里的突发任务、远程协作、风险把关和团队管理来讲产品价值。

核心表达：

> 人不在电脑前，也能远程指挥电脑里的 AI 干活；AI 可以自动执行，但关键动作有人值守。

## 2. 产品对外一句话

E-AgentCenter 是一个开源 AI 智能体指挥中心：把公司电脑、服务器或多台节点上的 Claude Code、Codex、OpenClaw、CrewAI、LangGraph、AutoGen 等智能体接入同一个控制台，统一派任务、看进度、查成本、做质量验收和人工值守。

短视频里不建议直接说“多智能体编排平台”。更适合说：

- 远程指挥电脑里的 AI 干活。
- 把公司电脑变成一支 AI 工作队。
- 不是远程桌面，而是远程派活。
- AI 自动干活，关键动作等人确认。
- 给 AI Agent 装一个任务看板、成本表和安全阀。

## 3. 已有能力对应的传播语言

| 代码/文档里的能力 | 对外传播语言 | 可拍画面 |
|---|---|---|
| 中心服 + 客户端 + Bridge | 人在外面，控制公司电脑/服务器上的 AI | 中心控制台、节点列表、Agent 在线状态 |
| Agent 管理 | 看见每个 AI 是否在线、正在干什么 | Agents 面板、状态徽标 |
| 本地会话聚合 | Claude Code / Codex 的会话都能统一看 | Chat / Sessions 列表 |
| Task Board | 像派员工一样给 AI 派任务 | 创建任务、任务从 assigned 到 in_progress |
| Human Watch 人工值守 | 危险操作先停住，等人批准 | 干预记录、规则、审批/拦截描述 |
| Aegis Quality Gate | AI 交付后先验收，不合格打回 | review / quality review 流转 |
| Cost Tracker | 每个 Agent 花了多少钱看得见 | 成本图表、模型分布 |
| Security Audit / Skill Scanner | 防止 AI 乱装、乱删、乱泄露 | 安全面板、扫描结果 |
| Recurring Tasks / Cron | 定时让 AI 做日报、巡检、同步 | Cron 面板、周期任务 |
| GitHub Sync / Webhooks | 和现有研发流程连接 | GitHub 面板、Webhook 配置 |
| Memory / Knowledge Graph | AI 的记忆和知识有迹可查 | Memory 图谱 |
| Multi Gateway / Nodes | 多台电脑、多处环境统一看 | Nodes / Gateway 面板 |

## 4. 场景清单

### S01 下班路上临时来需求

**真实触发**：下班路上，老板或客户发来消息：“这个 bug 今晚能不能先看一下？”

**用户焦虑**：人已经离开公司，代码和环境都在公司电脑；远程桌面在手机上很难操作。

**产品介入**：打开 E-AgentCenter，远程给公司电脑上的 Claude Code / Codex 创建任务；Agent 在原机器上读项目、查日志、跑测试。

**打动点**：不是远程控制电脑，而是远程指挥 AI。

**视频钩子**：

- “人已经下班，但公司电脑里的 AI 还能继续上班。”
- “我没回公司，只远程派了一个 AI 任务。”

**可拍画面**：手机消息、地铁/路上、Dashboard、Tasks 面板、Agent 执行中、结果进入 review。

### S02 人在外地，客户要临时方案

**真实触发**：出差、吃饭、开会途中，客户突然要竞品分析、报价草案或技术方案。

**用户焦虑**：资料、历史文档、项目上下文在办公室电脑或内部服务器，手机临时写不靠谱。

**产品介入**：远程派任务给 researcher / writer / reviewer 类 Agent；一个查资料，一个写草案，一个审核。

**打动点**：AI 不是聊天窗口，而是可以分工的远程工作队。

**视频钩子**：

- “客户临时要方案，我让办公室电脑里的 AI 先写初稿。”
- “一个 AI 查资料，一个 AI 写方案，一个 AI 审稿。”

**可拍画面**：任务拆成子任务、Agent 列表、任务看板、质量评审。

### S03 半夜线上故障，但不想打开 IDE

**真实触发**：半夜收到报警，服务报错或接口异常。

**用户焦虑**：人很困，打开电脑、翻日志、定位提交都耗时间；但直接让 AI 改生产又不放心。

**产品介入**：派任务让 Agent 分析日志、定位可疑代码、给出修复建议；部署、删文件、改配置前触发人工值守。

**打动点**：AI 先干脏活累活，人只做关键判断。

**视频钩子**：

- “半夜报警，我先让 AI 读日志。”
- “AI 可以救火，但部署前必须我点头。”

**可拍画面**：报警消息、任务创建、日志面板、安全/干预记录、review。

### S04 AI 想执行危险命令，被人工值守拦住

**真实触发**：AI 修问题时准备删除目录、修改 `.env`、安装未知依赖、重启服务或提交代码。

**用户焦虑**：AI 很勤快，但一旦误删、误改、误部署，损失比人工慢一点更大。

**产品介入**：Human Watch 监控 Worker 会话，命中规则后停住，记录干预，必要时模拟人工继续或要求换方案。

**打动点**：不是不信 AI，而是关键动作必须有人把关。

**视频钩子**：

- “我让 AI 干活，但没让它乱来。”
- “给 AI 装一个人工值守开关。”

**可拍画面**：Agent 执行、危险动作文字、干预记录、批准/拒绝/换方案的说明。

### S05 AI 写完代码，但必须先过质量验收

**真实触发**：AI 交付代码后看起来完成了，但可能没测、没考虑边界、没按需求做。

**用户焦虑**：AI 说“done”不等于真的 done。

**产品介入**：任务进入 review / quality review，由 Aegis 或 reviewer Agent 检查，不合格打回继续改。

**打动点**：把 AI 从“能交差”变成“可验收”。

**视频钩子**：

- “AI 说做完了，我不直接信。”
- “AI 交付也要过质检。”

**可拍画面**：任务从 in_progress 到 review，再到 quality review / done。

### S06 老板想知道 AI 一天到底干了什么

**真实触发**：团队里多个 AI Agent 全天跑任务，但管理者不知道产出、阻塞和异常。

**用户焦虑**：自动化越多，黑盒越多；不知道谁在忙、谁失败、谁空闲。

**产品介入**：Dashboard 汇总任务、Agent 状态、活动流、日志、节点健康。

**打动点**：AI 团队也需要管理看板。

**视频钩子**：

- “公司有了 AI 员工以后，老板最想看的不是聊天记录，而是工作台账。”
- “AI 团队一天干了什么，一个面板看清。”

**可拍画面**：Overview、Activity、Logs、Agents。

### S07 AI 成本失控，月底才发现花太多

**真实触发**：多个模型、多个会话、多个 Agent 同时跑，月底账单突然升高。

**用户焦虑**：不知道哪个 Agent、哪个任务、哪个模型最烧钱。

**产品介入**：Cost Tracker 展示 token、模型、会话、Agent 成本。

**打动点**：自动化不是越多越好，还要知道钱花在哪里。

**视频钩子**：

- “AI 帮你省时间，也可能悄悄烧钱。”
- “哪个 Agent 最贵，一眼看出来。”

**可拍画面**：Cost Tracker 图表、模型分布、会话成本排序。

### S08 每天重复汇报，让 AI 定时做

**真实触发**：每天早上要整理日报、站会摘要、昨天完成任务、今日风险。

**用户焦虑**：重复性工作低价值，但不做又影响团队同步。

**产品介入**：Recurring Tasks / Cron 用自然语言或 cron 定时创建任务，Agent 自动生成日报，结果进入 review。

**打动点**：把固定例行动作交给 AI，但保留审阅。

**视频钩子**：

- “每天 9 点，让 AI 自动写站会摘要。”
- “重复汇报不用天天手动催。”

**可拍画面**：Cron 面板、任务模板、生成的新任务。

### S09 客户资料可以整理，但发送前必须人工确认

**真实触发**：销售、咨询、投标、客服需要整理资料并发给客户。

**用户焦虑**：AI 可能把内部信息、敏感报价、未确认承诺发出去。

**产品介入**：Agent 先整理资料和初稿；涉及发送、报价、承诺、外部 webhook 时触发人工值守或质量审核。

**打动点**：AI 提高速度，人保留边界。

**视频钩子**：

- “AI 可以写客户回复，但不能替我拍板。”
- “资料让 AI 整理，发出去前我确认。”

**可拍画面**：任务、文档结果、审查/干预记录、Webhooks。

### S10 安装 Agent 技能前先安全扫描

**真实触发**：看到网上一个好用的 Agent skill / 插件，想装到本地 AI 工作流。

**用户焦虑**：技能里可能藏 prompt injection、读密钥、上传文件、危险命令。

**产品介入**：Skills Hub 安装前做安全扫描，检查凭据泄露、数据外传、混淆内容和危险 shell。

**打动点**：AI 生态越开放，安装前越要过安检。

**视频钩子**：

- “别随便给 AI 装网上的技能。”
- “AI 插件也要先过安检。”

**可拍画面**：Skills 面板、安全扫描结果、拒绝安装或确认安装。

### S11 GitHub Issue 自动同步给 AI 处理

**真实触发**：GitHub 上来了 bug / feature issue，团队希望先让 AI 做初步分析。

**用户焦虑**：issue 多时没人第一时间 triage；AI 分析后又难回到任务流。

**产品介入**：GitHub Sync 把 issue 同步成任务，分配给 Agent，处理结果进入看板和评审。

**打动点**：研发流程不用换，AI 接到现有工作流里。

**视频钩子**：

- “GitHub 一来 issue，AI 先帮我分诊。”
- “不是新开一个 AI 工具，而是接进原来的研发流程。”

**可拍画面**：GitHub 面板、Tasks 面板、任务详情。

### S12 多台电脑/服务器上的 AI 统一看

**真实触发**：公司电脑、家里电脑、云服务器、客户现场机器上都有不同 Agent。

**用户焦虑**：每台机器各看各的，状态分散，无法统一判断谁可用。

**产品介入**：中心服汇聚多个客户端节点，按 node_id、framework、Agent 状态统一展示。

**打动点**：把分散在各处的 AI 变成一个可管理的舰队。

**视频钩子**：

- “我有不止一台电脑在跑 AI，怎么统一管理？”
- “多台机器上的 AI，都接进一个控制台。”

**可拍画面**：Nodes、Agents、Gateway、Dashboard。

### S13 新员工/外包不碰服务器，只通过任务给 AI

**真实触发**：团队里有人需要触发自动化，但不应该直接拿服务器权限。

**用户焦虑**：直接给 SSH / 环境权限风险高；不给权限又影响效率。

**产品介入**：通过任务、角色权限、审批和审计，让操作者只发任务，由 Agent 在受控环境执行。

**打动点**：把危险权限变成可审计的任务流。

**视频钩子**：

- “不把服务器密码给别人，也能让他派 AI 干活。”
- “权限不下放，任务可以下发。”

**可拍画面**：Users / RBAC、Tasks、Audit。

### S14 AI 卡住等确认，人不在页面也能被值守续上

**真实触发**：Codex / Claude CLI 问“是否继续”“是否允许修改”“请选择方案”，用户没看到，会话停住。

**用户焦虑**：长任务跑到一半卡住，几个小时后才发现没进展。

**产品介入**：Human Watch 监视 transcript，识别确认类卡点、超时、工具挂起，按配置代发继续或提醒人工。

**打动点**：AI 长任务不再因为一句确认停一晚上。

**视频钩子**：

- “AI 跑长任务，最怕卡在一句确认。”
- “人不盯屏，值守 Agent 帮你盯。”

**可拍画面**：会话 transcript、Human Watch 配置、干预记录。

### S15 甲方临时改需求，AI 先评估影响面

**真实触发**：甲方在群里临时说“这个流程能不能顺便改一下？”

**用户焦虑**：马上答应风险高；不答应又显得响应慢。

**产品介入**：远程派 Agent 分析代码影响面、改动点、测试范围、风险和预计工作量。

**打动点**：先让 AI 做影响评估，人再回复客户。

**视频钩子**：

- “客户临时改需求，别急着答应，先让 AI 评估。”
- “AI 先看影响面，我再给客户报价和排期。”

**可拍画面**：创建评估任务、结果摘要、review。

### S16 老项目没人熟，AI 先画地图

**真实触发**：接手旧项目，没人能完整讲清模块关系。

**用户焦虑**：新人上手慢，改一处怕影响全局。

**产品介入**：Agent 扫描仓库、总结模块、生成知识文件；Memory / Knowledge Graph 记录关系。

**打动点**：AI 不只是改代码，也能帮团队建立项目记忆。

**视频钩子**：

- “接手老项目第一件事：让 AI 先画地图。”
- “没人讲得清的系统，让 AI 先整理成知识库。”

**可拍画面**：Memory Browser、知识图谱、任务输出。

### S17 投标/合同/报价场景的双人复核

**真实触发**：需要快速生成投标响应、合同条款、报价说明。

**用户焦虑**：金额、承诺、资质、交付范围不能让 AI 自作主张。

**产品介入**：AI 生成初稿，reviewer / Aegis 检查一致性；关键条款进入人工值守确认。

**打动点**：AI 负责速度，人负责责任。

**视频钩子**：

- “投标文件可以让 AI 起草，但不能让 AI 拍板。”
- “金额和承诺，必须人工确认。”

**可拍画面**：任务分工、review、干预记录。

### S18 团队周报自动生成，但数据来源可追溯

**真实触发**：每周要整理任务完成情况、成本、异常、下周计划。

**用户焦虑**：人工整理费时，AI 瞎编又不可用。

**产品介入**：从任务、活动、日志、成本和审计中汇总，让 AI 生成周报草稿。

**打动点**：让 AI 写报告，但内容来自系统真实记录。

**视频钩子**：

- “周报不是让 AI 编，是让 AI 汇总真实工作记录。”
- “AI 团队的周报，自动从任务和日志里生成。”

**可拍画面**：Activity、Tasks、Cost、导出结果。

## 6. 单条视频通用结构

建议每条控制在 45-70 秒。

| 时间 | 内容 | 目的 |
|---|---|---|
| 0-3 秒 | 真实突发事件 | 抓住注意力 |
| 3-10 秒 | 说出痛点 | 让用户代入 |
| 10-18 秒 | 打开控制台 | 引出产品 |
| 18-40 秒 | 展示一个核心动作 | 证明不是概念 |
| 40-55 秒 | 展示结果/把关/记录 | 建立可信度 |
| 55-70 秒 | 一句话总结 | 形成记忆点 |

结尾统一句式：

> 这不是一个聊天工具，而是一个 AI Agent 指挥中心。

或：

> 人可以离开电脑，但电脑里的 AI 工作流不用停。

## 8. 宣传表达禁区

不建议这样讲：

- “我们有 32 个面板、101 个 API。”
- “支持 WebSocket、SSE、SQLite、Zod、Next.js 16。”
- “多智能体编排平台，支持框架适配器。”

除非面向开发者深度视频，否则这些表达太抽象。

建议换成：

- “谁在干活，一眼看见。”
- “任务派出去，进度自动流转。”
- “AI 想做危险动作，先等人确认。”
- “每个 Agent 花了多少钱，看得清。”
- “公司电脑不在身边，也能让它里面的 AI 干活。”

## 9. 账号内容定位

账号可以围绕“真实 AI 工作流”建立，而不是只围绕某一个软件。

内容栏目建议：

1. **人在外面，AI 在干活**：远程派任务、公司电脑继续执行。
2. **AI 自动化安全边界**：人工值守、审批、审计、权限。
3. **AI 团队管理**：任务看板、成本、日志、质量验收。
4. **开发者真实场景**：修 bug、看日志、GitHub issue、代码评审。
5. **老板/团队场景**：日报、周报、客户方案、投标初稿。

## 10. 当前最强记忆点

优先主打这句话：

> 人不在电脑前，也能指挥电脑里的 AI 干活。

第二记忆点：

> AI 可以自动执行，但关键动作必须有人值守。

第三记忆点：

> 这不是又一个聊天窗口，而是 AI Agent 的任务、成本、安全和质量控制台。

## 11. 目标客户与付费理由

### 11.1 最优先客户：已经在用 AI 写代码的小团队 / 技术工作室

**典型人群**

- 3-30 人的软件外包团队、SaaS 小团队、独立开发团队。
- 团队里已经有人使用 Claude Code、Codex、Cursor、OpenClaw 或自建 Agent。
- 项目多、需求碎、经常临时救火。

**他们的真实痛点**

- AI 工具已经在用，但每个人各用各的，老板看不到进度。
- Agent 跑起来后不知道卡在哪里，常常几个小时后才发现没动。
- AI 生成代码后还要人工反复验收，过程没有记录。
- 多个模型和会话一起跑，成本不透明。

**为什么会花钱**

- 他们不是为了“尝鲜 AI”付费，而是为了把 AI 从个人工具变成团队生产力。
- 只要能少一个人盯任务、少一次线上事故、少几小时返工，就能覆盖工具成本。
- 对外包团队来说，响应速度和交付稳定性直接影响收入。

**最能打动他们的话**

> 你已经有 AI 工具了，现在缺的是一个能管理 AI 工作流的控制台。

### 11.2 高价值客户：有开发团队的中小企业老板 / 技术负责人

**典型人群**

- 有 5-50 人研发或数字化团队的企业。
- 老板或 CTO 想引入 AI 提效，但担心失控。
- 有内部系统、客户项目、运维任务、数据整理任务。

**他们的真实痛点**

- 老板听说 AI 能提效，但不知道团队到底有没有用起来。
- 技术负责人担心 AI 乱改代码、乱碰服务器、泄露资料。
- 管理层想看结果，不想看一堆聊天窗口。
- 需要权限、审计、质量把关，而不是纯个人版 AI 工具。

**为什么会花钱**

- 买的是“可控的 AI 自动化”，不是单个模型账号。
- 人工值守、审计、质量验收、成本追踪这些能力能降低管理风险。
- 自托管和本地节点对企业更有吸引力，数据不必全部交给第三方 SaaS。

**最能打动他们的话**

> 让员工用 AI 不难，难的是让 AI 工作过程可见、可控、可追责。

### 11.3 强场景客户：运维 / DevOps / 私有化部署团队

**典型人群**

- 管服务器、内网系统、客户现场机器的技术团队。
- 经常处理日志、巡检、重启、配置、部署、告警。
- 人不一定在机器旁边，但机器必须随时能处理问题。

**他们的真实痛点**

- 告警经常发生在晚上、路上、周末。
- 远程桌面/SSH 能解决，但操作负担大，而且容易误操作。
- AI 可以先分析问题，但高风险命令必须人工确认。
- 多台机器分散，状态难统一。

**为什么会花钱**

- 一次故障响应时间缩短，就有明确价值。
- 人工值守能让 AI 参与运维，但不把生产权限完全交给 AI。
- 多节点中心化管理适合私有化、客户现场和内网环境。

**最能打动他们的话**

> AI 可以先读日志、定位问题，但重启、删除、部署必须等人批准。

### 11.4 适合切入客户：AI 自动化爱好者 / 独立开发者 / 个人效率用户

**典型人群**

- 个人开发者、技术博主、自动化爱好者。
- 家里电脑、公司电脑、云服务器上都跑过 AI 工具。
- 喜欢搭建本地工作流和开源工具。

**他们的真实痛点**

- 工具多但分散，没有统一视图。
- 想远程让电脑继续跑任务。
- 想记录 AI 到底做了什么，方便复盘和分享。

**为什么会花钱**

- 个人用户付费能力较弱，但传播价值强。
- 他们会因为“远程指挥电脑里的 AI”这个新鲜场景安装、试用、录视频。
- 适合做开源社区、早期种子用户和口碑扩散。

**最能打动他们的话**

> 把你的电脑变成一个随时可远程指挥的 AI 工作站。

### 11.5 垂直行业客户：投标、咨询、法务、财务、销售支持团队

**典型人群**

- 经常写方案、标书、报价、合同、客户回复的团队。
- 有大量模板、历史材料、内部知识库。
- 文件可以让 AI 起草，但关键内容必须人工审核。

**他们的真实痛点**

- 重复文档工作多，时间紧。
- AI 生成快，但容易编错、漏条款、乱承诺。
- 金额、交期、法律条款不能让 AI 自己决定。

**为什么会花钱**

- 提高方案/投标/报价响应速度。
- 人工值守和质量审核能降低错误承诺风险。
- 如果能沉淀审计记录，适合团队内部追责和复盘。

**最能打动他们的话**

> AI 负责起草和整理，人负责确认和承担责任。

## 12. 付费意愿排序

| 优先级 | 客户类型 | 付费意愿 | 原因 |
|---|---|---|---|
| P0 | 小型研发团队 / 技术工作室 | 高 | 已经有 AI 使用习惯，马上需要团队化管理 |
| P0 | DevOps / 私有化运维团队 | 高 | 故障响应、安全审批、多节点管理价值明确 |
| P1 | 中小企业技术负责人 | 中高 | 预算更强，但需要信任、案例和私有化能力 |
| P1 | 软件外包 / 定制开发公司 | 中高 | 交付速度直接影响收入，适合场景化成交 |
| P2 | AI 爱好者 / 独立开发者 | 中低 | 传播力强，但付费价格敏感 |
| P2 | 投标/咨询/销售支持团队 | 中 | 场景成立，但需要行业模板和交付方案包装 |

## 13. 他们买的到底是什么

用户不会为了“一个控制台”付钱，他们会为了下面这些结果付钱：

1. **少盯屏幕**：AI 长任务有人值守，不用一直看着 CLI。
2. **少返工**：AI 交付进入质量验收，不是说 done 就算完成。
3. **少事故**：危险操作要确认，降低误删、误部署、误泄露风险。
4. **少沟通成本**：任务、日志、结果、成本都在一个地方。
5. **更快响应客户/老板**：人不在电脑前，也能远程派 AI 开始处理。
6. **更可控地引入 AI**：企业能看见 AI 在做什么、花多少钱、谁批准了什么。
7. **保留数据和环境控制权**：自托管、本地节点、公司电脑/服务器继续作为执行环境。

## 14. 最适合的商业包装

### 包装一：AI Agent 指挥中心

适合开发者和技术团队。

主卖点：

- 多 Agent 统一管理。
- 任务派发和进度追踪。
- 成本、安全、质量控制。

### 包装二：远程 AI 工作站

适合个人开发者、小团队、老板场景短视频。

主卖点：

- 人不在电脑前也能派活。
- 公司电脑/服务器上的 AI 继续干活。
- 手机或轻量设备只负责指挥和验收。

### 包装三：AI 自动化安全控制台

适合企业、运维、私有化客户。

主卖点：

- 人工值守。
- 危险操作审批。
- 审计留痕。
- 私有化部署。

### 包装四：AI 团队管理看板

适合老板、管理者、项目负责人。

主卖点：

- 谁在干活。
- 干到哪了。
- 花了多少钱。
- 结果有没有验收。

## 15. 当前最应该先打的人群

建议先从 **“已经在用 Claude Code / Codex 的开发者和小团队”** 切入。

原因：

1. 他们已经理解 AI Agent，不需要教育市场。
2. 他们已经遇到 CLI 卡住、任务分散、成本不清、结果难验收的问题。
3. 他们能接受开源、自托管、本地部署的产品形态。
4. 他们愿意尝试，也愿意在社交平台传播。
5. 他们的使用场景最容易拍成短视频：修 bug、看日志、改代码、跑测试、远程派活。

第二阶段再打 **DevOps / 企业私有化**，重点讲人工值守、安全审批和审计。

第三阶段再打 **投标、咨询、销售支持** 这类非研发团队，但需要额外包装行业模板，否则会觉得产品太技术化。
