# 测试用例-人工值守 V2：结构化事件与决策闭环

## 1. 测试范围

覆盖“结构化值守事件 + 决策回传 + 审计闭环”：

- Worker 主动 MCP 创建并等待事件。
- 值守 Agent 通过 MCP/API 决策。
- 人类 UI 决策。
- Gateway exec approval 镜像和回写。
- 规则引擎生成疑似卡住事件。
- 审计事件全链路。
- 授权与风险策略。

## 2. Worker 主动触发

### HW2-TC-001 Worker 创建值守事件

- 前置：托管 Codex 会话已由本地 Web/托盘启动，MCP 已注入。
- 步骤：Worker 调用 `mc_create_permission_request`，传入 `request_type=human_confirmation`、两个选项、`risk=medium`。
- 预期：
  - 返回 request id。
  - 平台待处理队列出现同一事件。
  - DB 中 `permission_requests.status=pending`。
  - 审计包含 `watch_event_created`。

### HW2-TC-002 Worker 等待批准后继续

- 前置：存在 pending 事件。
- 步骤：Worker 调用 `mc_wait_permission_request`；审批人选择 approve。
- 预期：
  - wait 返回 `status=approved`。
  - `selected_option_id` 等于批准选项。
  - Worker 继续执行被阻塞动作。
  - 审计包含 `decision_submitted` 和 `resume_succeeded` 或 `mcp_wait_returned`。

### HW2-TC-003 Worker 收到拒绝后停止

- 步骤：审批人选择 deny。
- 预期：
  - wait 返回 `status=denied`。
  - Worker 不继续危险动作。
  - 审计记录拒绝原因。

### HW2-TC-004 普通聊天不改变状态

- 步骤：值守 Agent 或用户只回复“同意”，不调用决策 API。
- 预期：
  - 事件仍为 `pending`。
  - Worker wait 不返回 approved。
  - 审计不产生 `decision_submitted`。

## 3. 值守 Agent 决策

### HW2-TC-010 值守 Agent 批准 medium 风险

- 前置：值守 Agent 有事件访问权限，事件 `risk=medium`。
- 步骤：调用 `mc_decide_permission_request(requestId, optionId=approve)`。
- 预期：
  - 状态变 `approved`。
  - `decider_type=steward_agent`。
  - 写入 `permission_request_decisions`。

### HW2-TC-011 未命中高危动作策略时默认值守 Agent 审批

- 前置：事件 `risk=high`，但动作不属于删除、卸载、覆盖、生产部署、付款、外部发送、密钥访问、提权等高危动作清单。
- 步骤：值守 Agent 调用决策 API 选择 approve 或 deny。
- 预期：
  - 平台接受值守 Agent 决策。
  - 决策记录 `decider_type=steward_agent`。
  - 不触发人工通知。
  - Worker 按 `resume_strategy` 恢复或停止。

### HW2-TC-012 命中高危动作策略时必须通知人工

- 前置：事件动作命中高危动作清单，例如删除文件、卸载应用、覆盖目录、生产部署、付款、外部发送、密钥访问或本地 CLI 提权。
- 步骤：值守 Agent 选择 approve。
- 预期：
  - API 默认返回 403 或转 `ask_human/notify_human`。
  - 平台推送到配置通知地址。
  - 不恢复 Worker。
  - 审计包含 `decision_rejected_by_policy` 或 `human_notification_sent`。

### HW2-TC-013 通知地址缺失时阻断

- 前置：事件命中高危动作策略，未配置通知地址。
- 步骤：值守 Agent 选择 `notify_human`。
- 预期：
  - 事件进入平台待审批队列。
  - 返回明确错误或警告：通知地址缺失。
  - Worker 不恢复。

### HW2-TC-014 人类收到通知后平台审批

- 前置：事件命中高危动作策略，通知地址已配置。
- 步骤：通知送达后，人打开审批链接选择 approve。
- 预期：
  - 决策记录 `decider_type=human_user`。
  - 平台按 `resume_strategy` 恢复 Worker。
  - 审计包含通知、决策、恢复结果。

### HW2-TC-015 人类在 Worker 会话回复后平台完成审批

- 前置：事件命中高危动作策略，通知已送达，Worker 会话仍在等待人工回复。
- 步骤：人直接回到 Worker 会话回复“批准执行”；本地托管端通过 `worker_human_reply_sync` 或 API 回写平台。
- 预期：
  - 平台将回复归档为 `decision_source=worker_session_reply`。
  - 决策记录 `decider_type=human_user` 或 `human_external`。
  - 事件状态从人工待处理转为 `decided/resolved`，不再停留在等待审批。
  - 审计包含 `human_notification_sent`、`worker_human_reply_received`、`decision_submitted`、`resume_attempted`。

### HW2-TC-016 Worker 本地回复未回写平台时不得视为完成

- 前置：事件命中高危动作策略，通知已送达。
- 步骤：构造 Worker 会话内出现“同意/批准”文本，但没有 `worker_human_reply_sync` 或平台决策 API 调用。
- 预期：
  - 平台事件仍保持人工待处理。
  - 不恢复 Worker。
  - 审计不产生 `decision_submitted`。
  - 诊断提示“Worker 回复未同步到平台”。

### HW2-TC-017 并发决策只接受一个最终结果

- 前置：事件处于人工待处理，平台 UI、值守 Agent、Worker 回复几乎同时提交决策。
- 步骤：并发提交 approve/deny/worker reply。
- 预期：
  - 只有第一个合法决策成功。
  - 其他请求返回 409。
  - 审计包含 `decision_conflict_rejected`。
  - Worker 只收到一次最终结果。

### HW2-TC-018 过期后 Worker 回复不得恢复执行

- 前置：事件已经 `expired`。
- 步骤：本地托管端随后同步一条“批准执行”的 Worker 回复。
- 预期：
  - API 返回 410 或等价错误。
  - 不恢复 Worker。
  - 回复归档为 late reply 审计。

### HW2-TC-019 边缘离线重连后旧回复不得覆盖新决策

- 前置：边缘离线期间人已在 Worker 回复；平台随后由人通过 UI 拒绝并完成事件。
- 步骤：边缘重连后同步旧 approve 回复，携带旧 `eventVersion`。
- 预期：
  - 平台拒绝旧回复。
  - 最终状态保持 UI 拒绝结果。
  - 审计包含版本冲突。

## 4. Gateway 执行审批

### HW2-TC-020 Gateway approval 镜像为值守事件

- 前置：Gateway 产生 `exec.approval`。
- 步骤：平台接收审批请求。
- 预期：
  - 创建 `event_type=exec_approval`。
  - 关联 `linked_gateway_approval_id`。
  - UI 可审批。

### HW2-TC-021 决策回写 Gateway

- 步骤：审批人批准 Gateway 事件。
- 预期：
  - 平台调用 Gateway 原审批接口。
  - Gateway 恢复执行。
  - 审计包含 `resume_attempted`、`resume_succeeded`。

### HW2-TC-022 Gateway 回写失败可见

- 步骤：模拟 Gateway 回写失败。
- 预期：
  - 事件状态为 `failed` 或恢复失败。
  - 可重试。
  - 审计包含错误信息。

## 5. 规则发现

### HW2-TC-030 规则命中只创建事件

- 前置：开启 V2 event-driven 模式。
- 步骤：构造 Worker transcript 命中 L1/L2/L3。
- 预期：
  - 创建 `event_type=suspected_stuck`。
  - 不直接调用 `session_continue`。
  - 审计包含 `watch_event_created`。

### HW2-TC-031 决策后才 bridge continue

- 前置：存在 `suspected_stuck` 事件，resume_strategy=`bridge_continue`。
- 步骤：审批人选择继续并填写 prompt。
- 预期：
  - 平台调用 Bridge `session_continue`。
  - Worker 会话出现 user turn。
  - 审计记录恢复成功。

### HW2-TC-032 同 fingerprint 去重

- 步骤：同一 transcript 状态重复触发规则。
- 预期：
  - 不创建重复 pending 事件。
  - 审计或诊断记录 `fingerprint_duplicate`。

## 6. 授权与租户隔离

### HW2-TC-040 未授权租户不可创建

- 前置：`enableHumanWatch=false`。
- 步骤：调用创建值守事件 API。
- 预期：403，不写 DB。

### HW2-TC-041 本地 CLI 提权未授权

- 前置：`enableLocalCliElevation=false`。
- 步骤：创建 `local_cli_approval` 或提权事件。
- 预期：拒绝或提示订阅，不允许批准提权。

### HW2-TC-042 跨租户不可见

- 步骤：租户 A 创建事件，租户 B 查询。
- 预期：租户 B 看不到事件和审计。

## 7. UI 验收

### HW2-TC-050 待处理队列统一展示

- 预期：权限请求、Gateway 审批、规则疑似卡住事件在统一队列展示。

### HW2-TC-051 事件详情展示完整上下文

- 预期：展示 Worker、客户端、风险、来源、选项、上下文、审计轨迹。

### HW2-TC-052 决策后实时更新

- 预期：事件状态、Worker 等待结果和审计列表同步更新。

## 8. 通知与可观测性

### HW2-TC-060 通知失败后不自动通过

- 前置：事件命中高危动作策略，配置 webhook 通知地址但目标不可达。
- 步骤：触发 `notify_human`。
- 预期：
  - 平台按策略重试。
  - 重试失败后事件仍在人工待处理。
  - 不恢复 Worker。
  - 审计包含 `human_notification_failed`。

### HW2-TC-061 通知敏感信息脱敏

- 前置：通知地址包含 token 或签名参数。
- 步骤：触发通知失败并查看日志/UI。
- 预期：
  - 日志和 UI 不显示完整 token/address。
  - 审计保留 target 标识和脱敏后的地址。

### HW2-TC-062 指标可用于排查

- 步骤：创建、通知、决策、恢复一个完整事件。
- 预期：事件量、决策耗时、通知成功/失败、恢复成功/失败等指标可观测。

## 9. 回归测试

- 旧 `permission_requests` 单测必须继续通过。
- Gateway exec approval 回写测试必须继续通过。
- 旧人工值守规则审计测试在 legacy 模式下继续通过。
- V2 event-driven 模式下规则不得直接代发。
