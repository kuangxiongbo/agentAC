## 3. 详细测试用例

### TC-001 统一 Agent 字段持久化

- 前置条件：数据库已迁移到包含 `node_id`、`framework`、`parent_id` 的版本。
- 步骤：
  1. 创建一个带 `framework` 和 `parent_id` 的 Agent。
  2. 从 API 或数据库读取该 Agent。
  3. 在 UI 中查看该 Agent 信息。
- 预期结果：
  1. 三个字段均被正确持久化。
  2. UI 能展示框架和层级信息。

### TC-002 客户端桥接上报到中心端

- 前置条件：中心端 bridge server 可启动，客户端已配置远端桥接地址。
- 步骤：
  1. 启动中心端。
  2. 启动客户端。
  3. 客户端发送 `hello` 与 `agent_status`。
  4. 在中心端查询 Agent 列表。
- 预期结果：
  1. 中心端接收到客户端连接。
  2. Agent 以桥接来源写入数据库。
  3. `node_id` 与 `framework` 信息完整。

### TC-003 本地 Agent 定义扫描

- 前置条件：本地存在 `~/.agents`、`~/.codex/agents` 或 `~/.claude/agents` 中的 Agent 定义。
- 步骤：
  1. 执行本地 Agent 同步。
  2. 查看本地数据库和 Agent 列表。
- 预期结果：
  1. 可识别目录或文件型 Agent。
  2. 变更会更新，缺失会标记离线。

### TC-004 Claude 会话扫描

- 前置条件：本地存在 Claude Code 项目与 JSONL 会话文件。
- 步骤：
  1. 触发 Claude 会话同步。
  2. 调用 sessions 接口读取合并结果。
- 预期结果：
  1. 能读取模型、消息数、token、活跃状态。
  2. 会话被纳入统一 sessions 视图。

### TC-005 Codex 会话扫描

- 前置条件：本地存在 `~/.codex/sessions` JSONL 文件。
- 步骤：
  1. 调用 sessions 接口。
  2. 查看是否存在 `codex-cli` 类型会话。
- 预期结果：
  1. 可识别 project、session、token、活跃状态。
  2. 数据与本地文件内容一致。

### TC-006 Hermes 会话与运行时检测

- 前置条件：本地安装 Hermes，并存在 `.hermes/state.db`。
- 步骤：
  1. 调用 Hermes 状态接口。
  2. 调用 sessions 接口。
  3. 调用 agent-runtimes 接口。
- 预期结果：
  1. 可识别 Hermes 安装与网关运行状态。
  2. Hermes 会话被纳入统一视图。

### TC-007 多框架接入路径区分

- 前置条件：系统可创建不同 `framework` 的 Agent。
- 步骤：
  1. 分别创建 `openclaw`、`claude`、`codex`、`generic` 类型 Agent。
  2. 观察其写入路径与行为差异。
- 预期结果：
  1. 各类型 Agent 均可创建。
  2. 非 OpenClaw 类型不会误走 OpenClaw 专属逻辑。

### TC-008 OpenClaw 条件化 Provision

- 前置条件：Provision 开关可配置。
- 步骤：
  1. 创建 `framework=openclaw` 的 Agent 并开启 Provision。
  2. 创建 `framework=claude` 的 Agent 并开启同样选项。
- 预期结果：
  1. OpenClaw 类型允许执行 Provision。
  2. 非 OpenClaw 类型被安全跳过，不触发错误命令。

### TC-009 新框架扩展可行性检查

- 前置条件：存在拟接入的新框架定义。
- 步骤：
  1. 根据设计文档新增 detector 或 adapter。
  2. 补齐桥接 payload 与 UI 字段。
  3. 执行对应测试。
- 预期结果：
  1. 新框架接入路径清晰。
  2. 无需修改大量无关模块。

### TC-010 文档链路完整性检查

- 前置条件：本轮进入编码前已完成文档更新。
- 步骤：

  2. 检查文档间是否存在相互引用。
- 预期结果：
