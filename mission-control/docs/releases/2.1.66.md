# 2.1.66 - Central Agent Inventory Synchronization Repair

Date: 2026-07-23

## Changes

- Restores explicit central-server mode in the 1Panel production Compose template with `MC_ENABLE_LOCAL_MONITORING=false`.
- Removes and suppresses legacy `source=bridge` Agent mirrors that duplicate the current Edge index after a deployment-mode correction.
- Updates `POST /api/server-sync/heartbeat` to refresh `sync_agent_index` from a complete Edge `agent_inventory` while the server is in clients-only mode.
- Preserves Human Watch bindings, sessions, tasks and existing Edge ownership boundaries.

## Artifacts And Upgrade

- Center image and Edge Web Runtime: `2.1.66`; native Tray remains `3.0.9`.
- No database migration or native Tray reinstall is required.
- Installed Tray `3.0.9` downloads the checksum-verified 2.1.66 Edge Runtime through the existing atomic updater.
- Roll back the Center image and Edge Runtime to `2.1.65`; restore the pre-deployment SQLite backup only if an operator also needs to undo production data cleanup.

## Verification

- Server and Edge typechecks, focused Agent sync tests, full suites, builds, release surfaces and artifact boundaries must pass.
- Production acceptance requires creating a local Agent and observing the same `local_agent_id/name` once on the Center without reconnecting the Bridge.
- Center mode must report `centralMode=true`; the Agent list must not contain duplicate Bridge/client cards.

## Gray Release Risk

- Older Edge Runtime versions do not emit every Agent lifecycle event; the HTTP heartbeat fallback keeps their inventory eventually consistent after the Center upgrade.
