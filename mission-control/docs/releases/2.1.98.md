# 2.1.98 - Automatic Steward Memory Activation

Date: 2026-08-03

## Changes

- Automatically activates steward memories after deterministic content, scope, and evidence validation.
- Adds reversible `disable` and `restore` actions while retaining `reject` and `approve` compatibility aliases.
- Keeps manually disabled memory disabled when later completed Goals produce the same content; new evidence is retained without silently reactivating it.
- Updates Center memory surfaces to show Active, Disabled, Expired, and Legacy Candidate states instead of requiring routine approval.
- Rejects unknown memory lifecycle actions instead of interpreting them as a state transition.

## Upgrade

- Upgrade Center and Edge Runtime to 2.1.98. Tray remains 3.0.10.
- No database migration is required. Existing `approved` rows are Active, `rejected` rows are Disabled, and legacy `candidate` rows can be activated manually.

## Rollback And Risk

- Roll back Compose to 2.1.97 and restore the pre-upgrade database backup if automatic activation causes unexpected behavior.
- Gray-release risk: newly extracted memories become available immediately. Operators should use Disable for inaccurate content; disabled exact matches remain sticky across later learning.
- Secret and scope validation remains mandatory before persistence; current session facts and safety policy remain higher priority than recalled memory.
