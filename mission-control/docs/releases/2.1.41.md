# 2.1.41 - Human Watch Queue Audit Completion

Date: 2026-07-09

## User / Operator Changes

- Reliable Human Watch mailbox delivery now writes a completed intervention audit record when the Edge runtime acknowledges a successful steward reply.
- Production validation records now show both the queued `intervention_attempt` and the final `intervention_completed success` for the same `message_id` / `correlation_id`.

## Server Image Contents

- Server version: `2.1.41`.
- Embedded Edge Web runtime version: `2.1.41`.
- Native tray version is unchanged.
- Docker tags: `agentcenter:2.1.41` and `agentcenter:latest`.

## Data / API / Migration Notes

- No database migration.
- Existing `edge_messages.result_json` remains the queue fact source.
- New acknowledgements for `human_watch.assist.requested` append `human_watch_interventions(event_type=intervention_completed, outcome=success)` with the steward reply preview.

## Verification

- `pnpm exec vitest run src/lib/__tests__/edge-messages.test.ts src/lib/__tests__/human-watch-assist-route.test.ts`
- `pnpm run typecheck`
- Production validation: queued Human Watch assist completed with `delivered=true` and steward reply `继续，按当前方案推进。`.

## Gray Release Risks

- This release only changes server-side audit completion for reliable mailbox acknowledgements. It does not change steward reply generation or Worker session delivery behavior.
