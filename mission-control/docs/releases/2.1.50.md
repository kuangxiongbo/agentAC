# 2.1.50 - Bounded Goal Snapshot And Atomic Scheduler Isolation

Date: 2026-07-16

## Changes

- Worker Goal reads now return a bounded schema 2 snapshot with every task's current state and dependencies, compact summaries, event counts and the latest 100 compact events.
- Raw task metadata and event evidence/action payloads remain in central audit storage and no longer inflate the Worker MCP response.
- `mc_get_task` now exposes read-only, non-destructive, idempotent and closed-world annotations for non-interactive fallback reads.
- Legacy scheduling identifies supervision ownership through task provenance, Goal metadata or the Goal-task relation. Candidate selection, claim, stale requeue, completion and failure writes all repeat the ownership conditions atomically.
- A legacy result is discarded if supervision takes ownership after the candidate query, preventing stale OpenClaw failures from overwriting Goal state.

## Production Evidence

- Retained failed Goal `d4d17ffb-c19f-465c-852f-44979c34aff2` proved the 2.1.49 Worker called `mc_get_supervision_goal`, executed `pwd`, submitted `mc_complete_supervision_task`, and triggered automatic activation of task 25.
- Its original Goal payload was truncated before the final task state. The fallback `mc_get_task` call lacked annotations and was cancelled.
- Task 25 was then requeued by the legacy stale scheduler after 10 minutes and attempted OpenClaw five times despite retaining Goal metadata and its relation. The Goal was formally failed and all evidence remains retained.
