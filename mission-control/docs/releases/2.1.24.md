# E-AgentCenter 2.1.24

Date: 2026-07-06

## Changes

- Adjusts human-watch transcript rules so Worker prompts that are waiting for user confirmation or a user answer can be handled by the bound steward agent when `awaiting_user_response` is enabled.
- Refines human-watch duplicate protection by adding a hash of the latest awaiting-user Worker message to the intervention fingerprint. Identical prompts still dedupe, but different confirmation questions can each trigger one steward intervention.
- Server image contents: embeds Edge runtime `2.1.24` and keeps tray native version unchanged at `3.0.7`.
- API/data/config changes: no schema migration.

## Upgrade Notes

- Deploy `agentcenter:2.1.24` and keep `latest` aligned.
- Installed Edge/tray clients should fetch runtime `2.1.24`; no tray DMG update is required.
- Existing human-watch bindings do not need to be recreated. Bindings with `awaiting_user_response` in `stuck_signals` can now let the steward agent answer Worker confirmation prompts after the idle threshold.

## Known Risks

- Awaiting-user intervention is intentionally limited by the existing idle threshold, duplicate fingerprint, and per-hour rate limit to avoid repeated automated replies.
- The validation host remains memory constrained. Keep swap and container limits in place; do not build on production.
