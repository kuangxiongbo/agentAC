# 2.1.101 - Agent-specific Codex Relay

Date: 2026-08-07

## Changes

- Adds an Agent-level `codex_model_provider` setting for managed Codex execution.
- Applies the selected provider to both dedicated-session creation and resume.
- Pins the default steward Agent 7 to `OpenAI3`, avoiding the unavailable `https://ai.myibc.net` relay inherited from global configuration.
- Validates provider identifiers before passing them to the Codex CLI.

## Upgrade

- Upgrade Center and Edge Runtime to 2.1.101. Tray remains 3.0.10.
- Installed Edge clients receive the replacement Web Runtime through the existing tray update flow.
- No database migration is required. Set `codex_model_provider` in the Agent config where an Agent must use a relay different from the global default.

## Verification

- Human-watch Judge and local-session focused tests: 28/28 passed.
- Edge TypeScript validation passed.
- Pre-release production probe: Agent 7 created a Codex session with `model_provider=OpenAI3`; Goal `12a30c66-46d7-43ff-a0ba-1f63658d8d92` completed with Worker MCP evidence and independent Agent 7 acceptance.
- Post-upgrade verification must repeat the goal while the global provider differs, proving the Agent-level override is effective.

## Rollback And Risk

- Roll back Center and Edge Runtime to 2.1.100; no database restore is required.
- A missing provider entry in the local Codex configuration still causes Codex startup failure. Invalid provider identifiers are ignored and logged.
