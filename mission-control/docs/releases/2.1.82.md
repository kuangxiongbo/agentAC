# 2.1.82 - Reliable Work Task Writeback

Date: 2026-07-27

## Changes

- Enables edit, status drag and delete for online `local_runtime` task projections.
- Queues every mutation through the reliable Edge mailbox instead of writing a cloud mirror.
- Requires client/workspace ownership, an allowlisted field set and optimistic `expected_updated_at` validation before the local SQLite transaction.
- Records local task activities and returns durable ACK/fail receipts; duplicate idempotency keys do not execute twice.

## API And Compatibility

- Adds `POST /api/tasks/local-mutations` and message type `work.task.mutation.requested`.
- Existing cloud task CRUD is unchanged. Comments, quality reviews and project/assignee remapping remain disabled for projected tasks.
- No database migration or configuration change is required.

## Artifacts And Upgrade

- Center image and Edge Web Runtime: `2.1.82`; native Tray remains `3.0.10`.
- The image embeds the matching Runtime ZIP and existing Tray DMG. Installed Tray clients fetch and atomically install Runtime `2.1.82`.
- Roll back Center and Runtime together to `2.1.81`; pending `work.task.mutation.requested` messages should be cancelled before rollback.

## Verification

- Center full suite: `1168/1168`; Edge full suite: `1011/1011`.
- Center writeback/projection focused suite: `5/5`; Edge mailbox/Bridge focused suite: `20/20`.
- Both typechecks, focused lint and production builds passed.

## Gray Release Risk

- Writeback is asynchronous. A `202` response means queued, while Edge ACK/fail and the refreshed projection are the final result.
- Concurrent local edits intentionally produce `TASK_VERSION_CONFLICT`; users must refresh and retry.
