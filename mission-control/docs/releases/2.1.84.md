# 2.1.84 - Reliable Human Watch Replies

Date: 2026-07-28

## Changes

- Human Watch automatic replies now use idempotent `session.continue.requested` mailbox messages instead of synchronous Bridge continuation.
- Intervention attempts, watch events and ACK-completed interventions share `message_id` and `correlation_id`.
- A queued reply is no longer reported as successful. Success is recorded only after Edge finishes the Worker CLI turn and ACKs the message; terminal delivery failure is audited as failed.

## Validation

- Focused Human Watch/mailbox suite: 4 files, 28 tests passed.
- Full Center suite: 145 files, 1174 tests passed.
- Focused lint, Center typecheck and production build passed.
- Production acceptance requires a real Worker question, semantic Steward answer in the same transcript, completed mailbox ACK and matching intervention message identity.

## Upgrade And Rollback

- Center upgrade is required. Existing Edge Runtime already supports completion-aware `session.continue.requested`; Runtime 2.1.84 keeps release surfaces aligned. Tray remains 3.0.10.
- Rollback to 2.1.83 requires no database rollback. Pending messages remain valid generic session continuations; 2.1.83 ignores the Human Watch payload metadata.

## Gray Risk

- Judge model latency is separate from the five-second rule debounce and remains under observation.
- Keep this release in small-scope production until real ACK correlation and reconnect idempotency pass.
