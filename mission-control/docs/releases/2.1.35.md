# 2.1.35 - Human Watch Binding Session Kind Persistence

Date: 2026-07-07

## User / Operator Changes

- Human Watch bindings now persist the Worker session type as `worker_session_kind` when a binding is created or updated.
- Existing bindings are backfilled from `sync_sessions.session_kind`, then from the Worker framework when possible.
- The orchestrator and diagnosis page prefer the stored kind before runtime inference, reducing `skip_reason=no_session_kind` when synced session data is stale or temporarily unavailable.

## Server Image Contents

- Server version: `2.1.35`.
- Embedded Edge Web runtime version: `2.1.35`.
- Native tray version is unchanged; the tray default runtime target is updated to `2.1.35`.

## Data / API / Migration Notes

- Adds nullable `human_watch_bindings.worker_session_kind`.
- `POST /api/human-watch/bindings` accepts optional `worker_session_kind`.
- `GET /api/human-watch/bindings` returns `worker_session_kind`.
- Binding session sync now updates both `worker_session_id` and `worker_session_kind`.

## Gray Release Risks

- Existing rows with no matching synced session and no recognizable Worker framework remain `NULL`; diagnosis will report missing session kind and operators should recreate or resync the binding.
- The migration is additive and rollback-safe for code, but downgraded images will ignore the new column.
