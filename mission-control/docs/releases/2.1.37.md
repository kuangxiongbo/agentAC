# 2.1.37 - Human Watch Judge Runtime Error Guard

Date: 2026-07-08

## User / Operator Changes

- Prevents Human Watch steward judge runtime errors from being auto-sent to Worker sessions.
- If the Edge steward CLI returns a model/runtime failure such as missing environment variables, API errors, authentication failures, or command failures, the Edge runtime now rejects the judge result.
- The center records the failure as `skip_reason=steward_judge_failed` instead of creating a successful `session_continue`.
- Production binding repair guidance remains: bindings must point to currently synced local steward agents; stale local IDs should be rebound before validating auto-send.

## Server Image Contents

- Server version: `2.1.37`.
- Embedded Edge Web runtime version: `2.1.37`.
- Native tray version is unchanged; tray default runtime target is updated to `2.1.37`.

## Data / API / Migration Notes

- No database migration.
- No HTTP API contract change.
- Bridge `steward_judge` behavior is stricter: obvious CLI/runtime error text is treated as a failed judge execution and is not eligible for auto-send.

## Verification

- `pnpm --dir mission-control-client test src/lib/__tests__/human-watch-judge.test.ts`.
- `pnpm --dir mission-control-client exec tsc --noEmit`.
- `pnpm run verify:release-surfaces` in `mission-control` before image publishing.
- Production verification should confirm new interventions no longer send `Missing environment variable` or similar runtime errors to Worker sessions.

## Gray Release Risks

- This release does not configure local model credentials for installed Edge processes. Operators must still ensure the tray/Edge runtime process has valid model environment or bind to a steward runtime that can execute successfully.
- Existing Worker messages that already received a runtime error before 2.1.37 are not rewritten.
