# 2.1.71 - Blocked Goal Retry Recovery

Date: 2026-07-23

## Changes

- Resumes a blocked Goal automatically when a steward retries or reassigns one of its Worker tasks.
- Records the automatic `blocked -> running` transition as a `goal_status_changed` supervision event.
- Preserves the existing Worker completion guard: MCP completion still requires a running Goal and an in-progress task.

## Artifacts And Upgrade

- Center image and Edge Web Runtime: `2.1.71`; native Tray remains `3.0.10`.
- No database migration or public request/response schema change is included.
- Installed clients update through the Center Runtime manifest.
- Roll back Center and Runtime to `2.1.70` if correction actions regress.

## Verification

- Focused correction tests include the blocked Goal retry transition.
- Production evidence must show a real Worker running beyond three minutes, writing an artifact, receiving `ok=true` from `mc_complete_supervision_task`, and only then ACKing its reliable message.
- Pre-release production diagnosis used Goal `c33fbd18-24de-4932-825d-a20703b2aece`, Task `47`, and reliable message `b2dabbd6-54fa-4617-924d-7ae6998ec9e9`: the Worker ran for 519 seconds, wrote a 62-shot/550-second storyboard, completed through MCP, and only then ACKed. The run exposed the blocked Goal recovery defect fixed here.

## Gray Release Risk

- Existing pending permission requests created while a Goal was blocked may still require an operator decision or cleanup; the release does not rewrite historical requests.
