# 2.1.34 - Human Watch MCP Trigger UI Alignment

Date: 2026-07-07

## User / Operator Changes

- Updates the Human Watch binding summary to show the current primary mechanism: Worker calls `mc_create_watch_event`, the platform creates a watch event, the steward Agent judges with context/memory/SOUL, then the reply is sent back to the Worker.
- Renames the old L1/L2/L3 trigger configuration to fallback scanning rules so operators do not mistake it for the primary Human Watch path.
- Keeps the legacy transcript scan available only as a compatibility fallback for Workers that do not proactively report via MCP.

## Server Image Contents

- Server version: `2.1.34`.
- Embedded Edge Web runtime version: `2.1.34`.
- Native tray version is unchanged.

## Upgrade Notes

- No database migration is required.
- Existing Human Watch bindings remain valid.
- Installed Edge runtimes may update to `2.1.34` only for version alignment; the production behavior change is in the center/server UI wording.

## Verification

- `pnpm run typecheck` in `mission-control`.
- `pnpm run verify:release-surfaces` before Docker publishing.
- Production smoke test after deploy: `/api/status?action=health` reports `2.1.34`, and the Worker binding Human Watch tab no longer lists L1/L2/L3 as the primary mechanism.

## Gray Release Risks

- The fallback scan settings still exist by design for compatibility. They should be interpreted as a fallback path; MCP-created watch events remain the expected primary path for managed Worker sessions.
