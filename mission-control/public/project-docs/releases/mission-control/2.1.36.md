# 2.1.36 - Human Watch Steward Daily Limit Alignment

Date: 2026-07-08

## User / Operator Changes

- Aligns newly created Edge Human Watch steward agents with the server default intervention budget: `60` interventions per `24` hours.
- Prevents newly created steward configs from carrying the legacy `6` intervention limit that could cause continuous watch tests to stop with `skip_reason=rate_limited`.
- Includes the latest assistant confirmation content hash in Human Watch rule fingerprints, so a new confirmation/waiting prompt is not skipped as `fingerprint_duplicate` just because it matches the same rule shape as an earlier successful intervention.
- Keeps tenant-level global rules authoritative for production orchestration.

## Server Image Contents

- Server version: `2.1.36`.
- Embedded Edge Web runtime version: `2.1.36`.
- Native tray version is unchanged.

## Data / API / Migration Notes

- No database migration.
- No HTTP API contract change.
- `human_watch_interventions.rules_hit` may now include `confirmation_text_hash` for confirmation-style prompts.
- Existing production tenant rule remains `max_interventions_per_hour=60` with `max_interventions_window_seconds=86400`.

## Gray Release Risks

- Existing steward agents that already saved custom lower limits in their local config are not rewritten automatically by this release.
- Historical visible watch events created before 2.1.35/2.1.36 are not backfilled; use a fresh Worker wait/confirmation prompt to validate current behavior.
