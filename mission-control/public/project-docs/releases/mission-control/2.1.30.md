# E-AgentCenter 2.1.30

Date: 2026-07-07

## Changes

- Adds memory-assisted human-watch judging. Before calling the steward Agent, the center can request bounded Edge-side memory search through Bridge, then fall back to center `memory_fts`; retrieved snippets are injected into the judge prompt as reference only and stored in `human_watch_events.context_json.steward_memory_context`.
- Fixes human-watch auto intervention when the Worker agent index is missing or stale but the session is still synced. The orchestrator now falls back to `sync_sessions.session_kind`, avoiding repeated `skip_reason=no_session_kind` for valid Worker sessions.
- Aligns local Edge and center watch-event card labels, including structured context and transcript summary labels.
- Server image contents: embeds Edge runtime `2.1.30`; tray native version remains `3.0.7`.
- API/data/config changes: adds Bridge `memory_search_request` / `memory_search_response`; no schema migration.

## Upgrade Notes

- Installed Edge clients must update to runtime `2.1.30` to answer Bridge memory search requests.
- Existing center-only behavior remains compatible; if Edge memory search times out or returns no results, the center continues without memory context or falls back to center FTS when configured.
- The production fix for `no_session_kind` requires the center image update; it does not require recreating bindings.

## Rollback

- Roll back the 1Panel compose image tag to `agentcenter:2.1.29`, pull, and recreate `mission-control`.
- Runtime rollback follows the previous `edge-runtime` manifest bundled in the `2.1.29` image.

## Known Risks

- Production memory search is bounded, but actual usefulness depends on Edge memory content. Current validation client may have little or no local memory data until users populate OpenClaw memory or file memory.
- The fix uses `sync_sessions` as a fallback. If a client stops syncing sessions entirely, intervention still requires a valid session kind from the binding trigger or agent framework.
