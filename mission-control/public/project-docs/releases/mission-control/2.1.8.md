# AgentCenter 2.1.8 Release Notes

Date: 2026-06-15

## Changes

- Fixes installed Edge runtime upgrades where `~/.e-agent-edge/runtime` was already updated but port `5101` still served an older in-memory Web process.
- The tray now verifies that `/api/status?action=health` reports the installed runtime version before accepting a local Web process as current.
- If a stale healthy process owns the local port, the tray recovers it with bounded process lookup, timeout handling, TERM, and KILL fallback before starting the current runtime.
- Runtime download progress now includes byte details in the main setup message.
- Closing the setup window now only hides it and keeps the tray/local Web service running; only the explicit menu-bar tray Quit action stops the local Web process.
- Publishes Edge Web runtime `2.1.8` and tray app `3.0.3`.

## Upgrade Notes

- Existing installed users need tray `3.0.3` to receive the stale-process recovery and close-window behavior.
- Existing runtime users will install runtime `2.1.8` from the updated service manifest after the production container is recreated.
- If the old `5101` process is still serving an older version, the tray should stop it and start the current runtime automatically.

## Verification

- `cargo check` in `mission-control-tray/src-tauri`
- `curl -fsS http://127.0.0.1:5101/api/status?action=health` returned `version: 2.1.7` after stale-process cleanup during pre-release diagnosis.
- `pnpm run verify:release-surfaces` after syncing docs, Edge runtime, and tray assets
- `pnpm run typecheck` in `mission-control`
- `pnpm run typecheck` in `mission-control-client`

## Known Risks

- Users running an older tray package will not receive native stale-process recovery until they install the new DMG.
- Installed-user end-to-end verification must be repeated against the deployed production image because the runtime and tray manifests are served by the container.
