# E-AgentCenter 2.0.3

Released: 2026-06-13

E-AgentCenter 2.0.3 is a production gray release for the managed Codex permission flow. It adds platform-owned permission requests, auditable approval decisions, and zero-touch MCP injection for Codex sessions started by the platform, local web client, or managed tray client.

## Highlights

### Managed Codex permission flow
- Platform-started Codex sessions now receive a temporary Mission Control MCP server through launch arguments.
- User terminal Codex sessions are not modified or taken over.
- The MCP tools allow a worker agent to create a permission request, wait for a decision, and continue execution after approval or rejection.
- Permission decisions are recorded with requester, approver, risk level, command context, and result metadata.

### Human and steward approval path
- The approval UI can show pending permission requests and stream updates through the existing realtime channel.
- Human operators can approve or reject requests from the platform.
- Steward agents can participate in lower-risk decisions through the same platform decision path.
- High and critical risk requests remain human-controlled for the gray release.

### Bridge and gateway hardening
- Local CLI elevation now includes audit context and grant tracking.
- Gateway execution forwarding records status compensation when an approval decision cannot be forwarded cleanly.
- Permission request APIs include rate and state guards to avoid duplicate or stale decisions.

### Release and update discipline
- The server image release process now requires release notes before Docker publishing.
- Edge runtime and tray artifacts must be verified before the image advertises a new client version.
- A shared release skill now defines common release gates, while this project keeps its own GitHub, image, validation, and deployment settings.

## Full Changelog

### Added
- Permission request persistence and service logic for create, wait, decide, and audit flows.
- Permission request APIs for managed agents and approval surfaces.
- MCP tools: `mc_create_permission_request`, `mc_wait_permission_request`, and `mc_decide_permission_request`.
- Dynamic Codex MCP launch injection for platform-managed sessions.
- Focused release documentation for server image contents and client upgrade behavior.
- Shared release workflow skill: `project-release-base`.
- Project-specific release workflow skill: `agentcenter-release`.

### Changed
- Platform-managed Codex execution now adds MCP configuration at process launch instead of requiring global user config edits.
- The default local MCP bridge URL for the managed client path is `http://127.0.0.1:5101`.
- Release process now requires GitHub commit and push before pushing the production Docker image.
- AgentCenter release metadata now keeps server, Edge web client, and tray client versions aligned for operator clarity.

### Fixed
- Avoided cross-user MCP or account leakage by scoping managed Codex injection to the launched session.
- Added stronger status handling when gateway approval forwarding fails after a decision.
- Reduced ambiguity between service version and client download version in release planning.

### Security
- Permission requests are auditable and tied to the session/agent context that requested them.
- Steward approval is restricted by risk level during gray release.
- No global Codex MCP config is written for unmanaged terminal sessions.
- GitHub and registry credentials must remain local secrets and must not be committed into release docs, images, or skill files.
