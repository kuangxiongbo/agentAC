# AgentCenter 2.1.18 Release Notes

Date: 2026-07-05

## Changes

- Fixed human-watch reply handoff: `mc_create_watch_event` now triggers `/api/human-watch/assist` when no permission options are supplied, asks the bound steward agent for a reply, and writes that reply back to the Worker session in `auto_send` mode.
- Preserved permission-request compatibility: `mc_create_watch_event` still falls back to `/api/permission-requests` when `options` are supplied.
- Added MCP session context propagation for platform-managed Codex sessions: `MC_WORKER_SESSION_ID` and `MC_SESSION_KIND` are injected for resumed/continued sessions so Worker tools can resolve the correct binding.
- Added `awaiting_user_response` as a default human-watch stuck signal and exposed it in the rule configuration UI.
- Added Edge local human-watch tables so local Web/tray runtimes have the required schema surface.

## Root Cause

The production binding was evaluating human-watch rules but returning `noop/no_rule_match` for normal “please confirm / which option” style Worker replies. Separately, the MCP tool path was only an alias for permission requests, so a Worker asking for continued confirmation did not actively invoke the steward agent or send the steward reply back into the Worker session.
