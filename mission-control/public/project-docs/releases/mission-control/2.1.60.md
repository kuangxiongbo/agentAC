# 2.1.60 - Upstream v2.2.0 Security Backport

Date: 2026-07-22

## Operator Changes

- Human Watch and Goal Supervisor Edge dispatch now carries bounded tools, working directory and per-task cost policy; Goal policy can only tighten Agent policy.
- Workspace audit records, search, export, status and cleanup are scoped by `workspace_id`.
- Agent names are unique per Workspace instead of globally.
- Strict Workspace mode permits only resources with authoritative local or Edge ownership; owned remote Worker sessions remain available to Human Watch and supervision.
- Remote Skill documents are limited to 256 KiB and critical workspace/config writes are atomic.

## Data And Security

- Migration `071_workspace_audit_and_agent_identity` adds audit ownership and rebuilds `agents` while preserving custom columns.
- Migration `072_workspace_isolation_policy` adds `brand` and `shared|strict` Workspace policy.
- Runtime installers are opt-in and version/hash pinned; CLI/MCP targets accept only bounded absolute HTTP(S) URLs.
- Default Docker base image is pinned to an OCI digest; root CodeQL, OSV and immutable Action pin gates are included.

## Artifacts And Upgrade

- Center image and Edge Web Runtime: `2.1.60`; native Tray remains `3.0.8`.
- The image includes the matching Edge Runtime ZIP, existing Tray 3.0.8 DMG and synchronized project docs.
- Standalone sanitization removes repository secrets/development files and duplicate embedded `public` assets before packaging.

## Verification And Rollback

- Server 1137 tests, Edge 994 tests, both typechecks/builds, release surfaces, artifact boundaries, and repeated production SQLite snapshot migration/restore rehearsal passed. Real production flow evidence remains a gray-release gate.
- Back up the SQLite volume before upgrade. Rollback image: `agentcenter:2.1.59`.
- Because `071` changes Agent uniqueness and `072` adds policy columns, code rollback retains additive schema; restore the pre-upgrade SQLite backup only if schema-level rollback is required.

## Gray Risks

- Existing historical foreign-key violations are retained but migration rejects newly introduced violations.
- Enable `strict` only after Edge clients and sessions have synced authoritative ownership metadata.
