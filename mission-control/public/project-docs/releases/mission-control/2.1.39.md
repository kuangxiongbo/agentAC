# 2.1.39 - Human Watch Web Conversation Stability

Date: 2026-07-08

## User / Operator Changes

- Fixes the production Human Watch path where a Web/local conversation was detected but the steward reply failed with `Bridge client disconnected`.
- Local Edge now rejects stale tray bootstrap `device.client_id` writes when `gateway.server_url` and `gateway.token` did not actually change.
- Bridge reconnect comparison now trims values and ignores trailing slashes in `gateway.server_url`.
- Human Watch rules now treat prompts such as `回答后说"确认"` / `回复后说"确认"` as high-confidence waiting-for-user signals.

## Server Image Contents

- Server version: `2.1.39`.
- Embedded Edge Web runtime version: `2.1.39`.
- Native tray version is unchanged; installed trays pull the updated Edge runtime from the center manifest.
- Docker tags: `agentcenter:2.1.39` and `agentcenter:latest`.

## Data / API / Migration Notes

- No database migration.
- `/api/edge/apply-bootstrap` now reports `skipped` keys when it refuses stale identity overwrite.
- Bridge reconnect is still allowed when the real upstream endpoint or token changes.

## Verification

- `pnpm --dir mission-control-client test src/lib/__tests__/edge-bootstrap-settings.test.ts`.
- `pnpm --dir mission-control exec vitest run src/lib/__tests__/human-watch-rules.test.ts`.
- `pnpm --dir mission-control run typecheck`.
- `NODE_OPTIONS='--max-old-space-size=8192' pnpm --dir mission-control-client run typecheck`.
- Production validation must confirm `human_watch_interventions` contains `intervention_completed outcome=success` after a Worker confirmation prompt.

## Gray Release Risks

- Old installed Edge runtimes can still be interrupted by stale tray bootstrap until they update to `2.1.39`.
- Existing stale `bootstrap.json` files are tolerated by the new runtime, but should be refreshed naturally on the next center bootstrap.
