# 2.1.63 - Managed Claude MCP Injection

Date: 2026-07-22

## Changes

- Platform-managed Claude Worker sessions now receive the Mission Control MCP server through a temporary `--mcp-config` on both session start and resume.
- The injected MCP process receives the bound Worker ID, Worker session ID, session kind and local permission mode.
- The MCP server can inherit the Runtime `API_KEY`, so installed Edge clients do not need a separate global Claude MCP profile.

## Artifacts And Upgrade

- Center image and Edge Web Runtime: `2.1.63`; native Tray remains `3.0.9`.
- Installed Tray `3.0.9` users receive this fix through the Runtime updater. No native Tray reinstall or database migration is required.
- Roll back the center image and Runtime to `2.1.62` if managed Claude sessions cannot start.

## Verification

- Focused MCP injection tests, full Server/Edge test suites, typechecks and production builds must pass before publishing.
- Runtime ZIP SHA-256: `c0751addb5612eb7023c66a89ce80e493ebc57c08c6e100a879276c37e8417d2`.
- A real Claude CLI invocation without a global MCP profile must call `mc_session_transcript` successfully using inherited Runtime authentication.
- Production acceptance requires a Worker question, `mc_create_watch_event`, `intervention_completed success`, reliable Edge message acknowledgement, and a semantically relevant Steward reply in the same Worker transcript.

## Gray Release Risk

- Existing unmanaged Claude sessions are unchanged because MCP injection is limited to platform-managed execution.
- Keep Human Watch binding auto-stop enabled and disable the test binding immediately after production evidence is collected.
