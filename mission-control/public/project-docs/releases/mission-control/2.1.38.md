# 2.1.38 - Edge Bridge Bootstrap Reconnect Guard

Date: 2026-07-08

## User / Operator Changes

- Fixes unstable Human Watch production validation where the center timed out while requesting local Edge transcripts.
- Edge now keeps the Bridge websocket alive when the tray periodically reapplies identical bootstrap settings.
- Tray heartbeat-style fields such as `edge.enrolled_at` no longer trigger `restartRemoteBridge()`.
- Bridge reconnect is limited to actual changes in `gateway.server_url`, `gateway.token`, or `device.client_id`.

## Server Image Contents

- Server version: `2.1.38`.
- Embedded Edge Web runtime version: `2.1.38`.
- Native tray version is unchanged; tray default runtime target is updated to `2.1.38`.
- Docker image publishing is deferred for this small gray release because local Docker free space is below the release floor; the Edge runtime zip and manifest can be published as static assets.

## Data / API / Migration Notes

- No database migration.
- No HTTP API contract change.
- Local Edge endpoints `/api/edge/apply-bootstrap` and `/api/edge/import-tray-config` still persist incoming tray settings, but reconnect the Bridge only when connection-critical values actually change.

## Verification

- `pnpm --dir mission-control-client test src/lib/__tests__/edge-bootstrap-settings.test.ts src/lib/__tests__/edge-tray-config-file.test.ts`.
- `NODE_OPTIONS='--max-old-space-size=8192' pnpm --dir mission-control-client run typecheck`.
- Production gray verification should confirm Bridge reconnect count stops increasing every tray bootstrap cycle and Human Watch can fetch Worker transcripts through the Bridge.

## Gray Release Risks

- This release stabilizes the local Edge Bridge, but production image `2.1.37` is not rebuilt until Docker space is cleaned.
- Installed Edge clients must update to runtime `2.1.38`; old `2.1.36/2.1.37` runtimes still restart Bridge on repeated tray bootstrap writes.
