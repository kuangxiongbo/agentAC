# 2.1.55 - Persisted Codex Project Directory

Date: 2026-07-16

## Changes

- Resuming a managed Codex session now uses the Agent's persisted `mc_session_project_path` instead of inheriting the Edge Runtime server cwd.
- Existing Worker/session identity and managed MCP environment injection remain unchanged.
- A regression test verifies the persisted directory wins when the caller provides another cwd.

## Upgrade And Verification

- Installed clients update Web Runtime to 2.1.55. Tray remains 3.0.8.
- The runtime package, MCP server, manifest and Center compatibility version must all report 2.1.55.
- Runtime ZIP SHA-256: `032e1beb6a2797870e9301d73ef21031b54e8e288ceb73453f094d75393cc35c`; Tray 3.0.8 DMG SHA-256: `b013f918a731862020c809a2c648b3398d1212862ef77bc4f249afd734081db8`.
- After update, verify a repository-bound Worker resumes in the configured repository and completes a read-only Git command through the supervision MCP flow.

## Known Risk

- A Worker whose persisted path is an isolated non-Git directory will still reject repository-only commands. Configure the intended project path before dispatch; do not infer one from the Center process cwd.
