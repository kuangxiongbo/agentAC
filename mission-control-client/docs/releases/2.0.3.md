# E-AgentCenter Client 2.0.3

Released: 2026-06-13

E-AgentCenter Client 2.0.3 aligns the Edge web client and managed tray client with the server-side permission request flow. The focus is zero-touch MCP injection for platform-managed Codex sessions, clear upgrade behavior for installed users, and consistent client/server version reporting.

## Highlights

### Zero-touch MCP injection for managed Codex
- Codex sessions started by the platform, local web client, or managed tray client can receive the Mission Control MCP server automatically.
- The injection is process-scoped through Codex launch arguments and does not write global Codex configuration.
- Codex sessions started directly by users in a terminal are unchanged for this release.

### Permission request integration
- Managed Codex can ask the platform for approval before running sensitive commands.
- The platform can route the decision to a human operator or a steward agent, depending on risk policy.
- After a decision, Codex continues execution through the original local process path.

### Installed client update behavior
- The server release must include the matching Edge runtime and tray artifacts before advertising client version `2.0.3`.
- Installed tray clients should receive upgrade prompts only when the update manifest points to the new version and artifact.
- New downloads should show the unified client version so operators do not have to compare separate tray and web labels.

## Full Changelog

### Added
- Shared Codex MCP injection helper for the client runtime.
- Focused tests covering managed-session MCP launch arguments.
- Client release notes describing installed-user upgrade expectations.

### Changed
- The managed MCP bridge default URL is `http://127.0.0.1:5101`.
- The client can override the MCP URL through managed environment settings such as `MC_MANAGED_MCP_URL` or `MC_URL`.
- Version management should stay aligned with the server image release version.

### Fixed
- Avoided requiring users to install MCP manually for Codex sessions started through the managed client path.
- Avoided changing unmanaged terminal Codex behavior.
- Reduced confusion between Edge web client, tray client, and server image versions by documenting the unified release version.

### Security
- Managed MCP injection is limited to sessions launched by trusted platform/client code.
- The client should not persist GitHub, registry, or platform secrets into logs, release docs, or bundled assets.
- Approval decisions remain platform-mediated and auditable.

### Verification
- `cd mission-control-client && pnpm run typecheck` passed.
- `cd mission-control-client && pnpm exec vitest run src/lib/__tests__/codex-mcp-injection.test.ts src/lib/__tests__/local-cli-permission.test.ts` passed.
- Temporary launch-time MCP configuration was verified without writing global Codex config.

## Upgrade Notes

- Client version target: `2.0.3`.
- Server image version target: `2.0.3`.
- Installed users need the updated tray artifact and update manifest to receive upgrade prompts.
- Users who start Codex outside the managed platform/client flow will not receive automatic MCP injection in this release.

## Known Gray-Release Risks

- Verify the tray updater manifest and DMG/update artifact before publishing the server image.
- Observe whether installed clients reliably discover the new client version after deployment.
- Keep enterprise takeover for user-owned terminal Codex sessions behind a future explicit setting.
